# BigSurVPN: приложение и обновление по кнопке

## Что реализовано

Это начальная нативная часть будущего приложения, а не готовая замена Happ.
В этой поставке реализован центр обновлений приложения: окно SwiftUI, пункт меню,
проверка конфигурации доверенного канала, подключение Sparkle и инструменты выпуска.
Кнопка «Проверить обновления» вызывает стандартный процесс: поиск версии → список
изменений → загрузка → проверка подписей → установка с подтверждением → перезапуск
приложения. Ошибки сети и подписи обрабатываются Sparkle; это не «успешное обновление».

Улучшения приходят в опубликованных разработчиком версиях. Кнопка не запускает ИИ,
не генерирует код на устройстве и не исполняет меняющиеся shell-скрипты из main.

## Границы этой поставки

- GUI управления подключением, импорт ссылок и привилегированный XPC-helper пока не
  реализованы. В окне нет фиктивной кнопки подключения.
- Обновляется только `.app`. Существующие `/Library/BigSurVPN`, sing-box, launchd,
  профили и пароли не читаются, не переписываются и не отключаются.
- Поэтому это НЕ обновление установленного CLI 2.1.3 и НЕ исправление причины его
  сетевых обрывов. `vpn-bigsur update` по-прежнему означает обновление подписки.
- Обновление привилегированной службы требует отдельного доверенного установщика
  с проверкой совместимости, фиксацией старого состояния и испытанным откатом.
  Нельзя просто заставить Sparkle/GUI запускать загруженный скрипт от root.
- Готового подписанного `.app`, настоящей ленты и действующих ключей в исходниках
  нет. Тестовые сборки явно показывают это и не запускают автообновление.

## Выбранная технология и безопасность

SwiftUI/AppKit, цель macOS 11.0 Intel. Sparkle **2.9.6** закреплён на commit
`ac2def288cbff5cfc7df3ffef6abdf45b72bcb0a`; его SwiftPM-пакет проверяет архив framework
по SHA-256. Это совместимая с Big Sur линия; Sparkle 2.10 поднял минимум до macOS 12.
Обновлять эту зависимость на 2.10 без отдельного решения о поддержке Big Sur нельзя.

Защитные настройки: HTTPS; Ed25519-подпись пакета; проверка перед распаковкой;
обязательная подпись ленты; запрет снятия этого требования по тайм-ауту;
отключённые JavaScript и сбор системного профиля; отсутствие фоновой установки.
Само приложение не запускается от root. Закрытый ключ остаётся в Keychain издателя.

В стабильной линии номер сборки только возрастает, предварительные версии не
выбираются автоматически. Release notes — простой текст, без скриптов и загрузки
внешних страниц. Ошибка скачивания/проверки не запускает наш код изменения VPN.

Обновление окна приложения при работающем внешнем VPN допустимо: `.app` не владеет
этой службой и не вызывает её остановку. Политика `VPNActivity` уже предусматривает
блокировку кнопки во время будущих операций подключения/отключения/замены службы;
фактический менеджер подключения должен передавать ей своё состояние при интеграции.
Эта политика сама по себе не является существующим менеджером VPN.

## Локальные проверки

```sh
swift test --package-path vpn-app
python3 -m unittest discover -s vpn-app/tests -v
```

На Linux собирается только модуль правил и выполняются его тесты; SwiftUI, AppKit и
Sparkle нельзя считать собранными по результату Linux-тестов. GitHub Actions отдельно
пытается собрать нативное приложение на `macos-15-intel` без production-секретов.
Артефакт такой сборки — development ZIP, НЕ распространяемый подписанный выпуск.

Сборка на новой macOS не заменяет проверку запуска и обновления на Big Sur 11.
Локальные unit-тесты проверяют правила и метаданные, а не сам установщик Sparkle.

## Сборка тестового окна на Mac

Нужен Mac-сборщик с Xcode, Swift 5.7+ и Python 3.8+. На компьютере конечного
пользователя Xcode не потребуется после появления подписанного `.app`.

```sh
python3 vpn-app/tools/build_release.py build \
  --development --output /tmp/BigSurVPN.app
```

Скрипт не ставит Xcode/Homebrew, не требует sudo и не перезаписывает существующий
output. SwiftPM получает закреплённый Sparkle; собирается Intel-приложение, framework
копируется с сохранением ссылок, проверяются архитектура и фактические Mach-O minOS,
выполняется локальная ad-hoc подпись. Эта сборка позволяет проверить UI, но обновление
в ней намеренно выключено: ключ и release-канал не настроены.

## Однократная настройка издателя

Потребуются **два разных вида подписи**: Developer ID Application для подписи и
нотариализации приложения Apple, а также Ed25519 для пакетов и ленты Sparkle.
Ни сертификат с закрытым ключом, ни пароль Apple ID передавать в чат не нужно.

В дистрибутиве Sparkle 2.9.6 / SwiftPM-артефакте доступны `generate_keys` и
`sign_update`. На защищённом Mac издателя выполнить:

```sh
/path/to/sparkle/bin/generate_keys --account ru.pioner22.BigSurVPN.updates
export SPARKLE_PUBLIC_KEY="$(/path/to/sparkle/bin/generate_keys --account ru.pioner22.BigSurVPN.updates -p)"
```

Закрытый ключ хранится в Keychain. Резервную копию держать вне репозитория и вне
публичной раздачи обновлений. После потери ключа может потребоваться доверенная
ручная переустановка; система не отключает проверку подписей для «удобства».
Настроить `notarytool` keychain profile штатными средствами Apple.

## Подготовка настоящего выпуска

Изменить `release.json` (версия и возрастающий build), написать release notes.
Из корня репозитория:

```sh
python3 vpn-app/tools/build_release.py build \
  --identity 'Developer ID Application: YOUR NAME (TEAMID)' \
  --output /tmp/BigSurVPN.app

python3 vpn-app/tools/build_release.py prepare \
  --app /tmp/BigSurVPN.app \
  --sparkle-tools /path/to/sparkle/bin \
  --notary-profile bigsurvpn-notary \
  --team-id YOURTEAMID \
  --notes /path/to/release-notes.txt \
  --first-release \
  --output /tmp/BigSurVPN-release-1
```

`YOURTEAMID` — настоящий 10-символьный Team ID. Для следующего выпуска вместо
`--first-release` обязателен `--previous-feed /path/to/current/appcast.xml`.
Предыдущая лента проверяется ключом издателя; build должен быть больше всех прежних.
`--first-release` применяется только при создании канала, не для обхода нумерации.

`prepare` работает с временной копией `.app`: проверяет подпись/Team ID/ключ,
передаёт архив в Apple notarization, требует Accepted, прикрепляет и проверяет
билет, выполняет Gatekeeper assessment, создаёт финальный ZIP, подписывает его,
формирует и подписывает appcast, повторно проверяет обе подписи.

Выходной каталог содержит ZIP, appcast.xml, release notes и release.json. Скрипт
**не публикует** выпуск и не заменяет работающую программу. Перед распространением
нужно пройти приведённые ниже испытания. Затем сначала загрузить ZIP в GitHub Release
с тегом из release.json, после этого опубликовать подписанный appcast.xml по пути
`vpn-app/updates/appcast.xml` в main. Старые ZIP не удалять. Feed не форматировать после
подписи: любое изменение требует повторной подписи. Git attributes отключают CRLF.

Для пользователя после первой установки: открыть BigSurVPN → «Проверить обновления»
→ прочитать изменения → подтвердить установку. Повторять curl-команду не потребуется
для обновления приложения. Старый CLI от этого автоматически не обновляется.

## Обязательные испытания перед первой публикацией

На настоящем Intel Mac с Big Sur проверить установку N → N+1 с рабочим VPN,
отмену загрузки, недоступную ленту, потерю сети при скачивании, неверную подпись,
подменённый ZIP, несовместимую ОС, отказ авторизации, недостаток места и запуск новой
версии. Проверить, что служба и настройки VPN остаются прежними. Зафиксировать SHA-256
обоих архивов, build, версии ОС и результат каждого сценария. Автоматический откат
при программной ошибке новой версии этой поставкой не реализован; не заявлять его.
