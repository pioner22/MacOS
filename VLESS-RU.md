# VLESS для Intel macOS Recovery — экспериментальная версия 0.1.1

Отдельный помощник `vless.sh`; старый `proxy.sh` не заменяется. В публичном коде нет личной ссылки, UUID, пароля или персонального профиля. Совместимость с реальным Recovery и стабильность компьютера не подтверждены локальными тестами.

## Исправление 0.1.1

`openssl` больше не является обязательной утилитой. Для SHA-256 выбирается установленная и работающая реализация: `shasum`, `sha256sum`, `sha256`, `openssl`, Perl с Digest::SHA или Python с hashlib. Перед использованием проверяются известные хеши пустого ввода и `abc`. Наличие команды без успешного запуска не считается достаточным. Ошибка запуска/отсутствие модуля допускает другой вариант; код аварийного завершения останавливает проверку. Если ничего не подходит, выводится `MISSING_CAPABILITY=working_SHA256`. Проверка контрольной суммы не отключается, пакеты автоматически не устанавливаются.

Новый режим `doctor` не скачивает клиент, не читает VLESS-ссылку, не создаёт каталог состояния и не меняет маршруты, DNS или системный прокси. Он проверяет наличие требуемых команд, вычисление SHA-256 и вывод версии/архитектуры. `PREFLIGHT_OK` не является тестом RAM, оборудования или совместимости sing-box.

Для `status` и `stop` не нужны curl или утилита SHA-256. Если каталога состояния нет, сообщается об отсутствии запущенного клиента в этой сессии.

## Важно при авариях curl

`malloc: Incorrect checksum for freed object` / `Abort trap: 6` — сообщение о повреждении памяти процесса, не несовпадение SHA-256 скачанного архива. По нему нельзя единолично установить аппаратную причину. Это исправление зависимости не устраняет такую аварию.

Если сообщение повторяется, не запускайте prepare/start и не продолжайте установку в этой сессии. Сохраните снимок/журнал, проверьте отдельную среду восстановления и оборудование. Повторное форматирование не является способом устранения ошибки памяти curl.

## Скачивание и первичная проверка

```bash
curl -q -fL "https://raw.githubusercontent.com/pioner22/MacOS/rescue/vless.sh?v=011" -o /tmp/vless.sh && echo DOWNLOAD_OK
```

Путь — `/tmp/vless.sh`, с точкой перед `sh`, не `/tmp/vless/sh`. При HTTP-ошибке, ошибке записи или аварии curl не исполняйте полученный файл, даже если счётчик достиг 100%.

Только после `DOWNLOAD_OK` и без сообщений об аварии:

```bash
bash -n /tmp/vless.sh && bash /tmp/vless.sh doctor
```

При наличии предыдущих полных зависаний сначала разберите результат doctor и состояние системы. Не включайте TUN автоматически после preflight.

## Проверка соединения без системной маршрутизации

После успешного preflight, без параллельной установки и других прокси:

```bash
bash /tmp/vless.sh prepare
```

Ссылка вводится в скрытый запрос, не отдельной командой оболочки. Можно передать путь к локальному файлу с одной строкой URI, заключив путь с пробелами в кавычки. Не публикуйте этот файл.

Используется VLESS + REALITY + XTLS Vision + TCP + fp=chrome. `spx`/Xray spiderX не преобразуется в отсутствующее поле sing-box; пригодность профиля проверяется соединением. SSH и Python на сервере не требуются.

Ядро — официальный sing-box 1.14.0 `darwin-amd64-legacy-macos-10.13`. Метка старой macOS не доказывает поддержку Recovery. Перед запуском сверяется SHA-256 архива, затем выполняются `version` и `check`.

Метаданные релиза: https://api.github.com/repos/SagerNet/sing-box/releases/assets/537409689

SHA-256 архива: `99285bb2d30739dc8884144cf90f50538336eab9914ac4524290f5b82fdb5565`.

`prepare` временно создаёт mixed-прокси только на `127.0.0.1:2080`, делает HTTPS HEAD к www.apple.com через явно заданный SOCKS и завершает тестовый процесс. Системные маршруты/DNS/прокси не меняются. Ожидается `VLESS_TEST_OK`. Один адрес не доказывает доступность установочных пакетов или стабильность TUN.

## TUN — отдельное подтверждение

Только после успешной проверки соединения и оценки стабильности:

```bash
bash /tmp/vless.sh start
```

Нужно ввести `TUN`. sing-box пытается создать `utun19`, маршруты IPv4/IPv6 и native DNS. Существующий utun19 не заменяется. Исходящие соединения привязаны к исходному en*-интерфейсу для предотвращения петли. До `TUN_READY` проверяются два контрольных маршрута и один IPv4 HTTPS-запрос. При неудаче посылается TERM; принудительный сброс маршрутов не выполняется.

Нет ограничения только доменами Apple. Предполагается интернет-трафик TCP/UDP, не каждый IP-пакет. Локальные/более специфичные маршруты, bootstrap DNS и управляющее соединение — исключения. DNS приложений обрабатывается через DoH/VLESS; разрешение адреса VPN-сервера использует выбранный текущий IPv4 resolver напрямую.

Нет изменений pf, T2/SIP, ремонта/стирания дисков или цикла повторного применения scutil. Клиент работает в фоне, игнорируя обычный HUP, только в текущей сессии. Перезагрузка/смена Recovery/полное зависание прервут туннель. На экране глобуса он не действует.

```bash
bash /tmp/vless.sh status
bash /tmp/vless.sh stop
```

Остановка отправляет TERM только процессу с проверенным путём клиента. Уборка маршрутов/DNS делегирована sing-box. Если utun19 остался, выводится ошибка; чужие интерфейсы не удаляются. После остановки или аварии прямой доступ может возобновиться: это не kill switch.

Приватные настройки и журналы: `/private/tmp/recovery-vless` (700), JSON с UUID (600). Не публикуйте каталог целиком или конфигурацию.

## Проверки изменения

37 локальных тестов прошли на Linux/Bash: 20 прежних тестов с обновлённой проверкой версии и 17 новых. Новые тесты включают реальное вычисление SHA-256 через шесть доступных реализаций на восьми наборах данных, работу без OpenSSL, отказ при неправильном хеше/аварийном коде, режим doctor без сетевых операций и отсутствие зависимости от SHA-256/curl при остановке.

Проверка JSON в прежних тестах использует заглушку sing-box check, не настоящий клиент. Реальный сервер, macOS/Bash 3.2, legacy sing-box, маршруты/DNS и TUN в этой среде не запускались. Исправление не считается решением прежних зависаний.

Скрипт 0.1.1: коммит `ebb6636d7d2474e0881710f1fab1537d40977a29`, SHA-256 `e11873266c82e922df44c16c62b45e7c85b183cd8e50da6f1590a145963b658b`.
