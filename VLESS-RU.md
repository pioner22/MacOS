# VLESS для Intel macOS Recovery — экспериментальная версия 0.1.0

Отдельный помощник `vless.sh`; старый `proxy.sh` не заменяется. В публичном коде нет личной ссылки, UUID, пароля или готового персонального профиля.

## Возможности и ограничения

Прямое подключение к серверу из ссылки, без SSH и без Python на сервере. Поддерживается VLESS + REALITY + XTLS Vision + TCP + fp=chrome. Параметр `spx` (Xray spiderX) не преобразуется в несуществующее поле sing-box; скрипт явно сообщает об этом. Пригодность профиля нужно проверить реальным соединением.

Используется официальный sing-box 1.14.0 `darwin-amd64-legacy-macos-10.13`. Обозначение старой macOS не подтверждает совместимость с Recovery. Перед исполнением проверяется SHA-256 архива, затем `version` и `check`. На этапе разработки скачивание бинарного архива не удалось; реальное ядро, macOS Recovery и TUN здесь не запускались.

Метаданные релиза: https://api.github.com/repos/SagerNet/sing-box/releases/assets/537409689

SHA-256 архива: `99285bb2d30739dc8884144cf90f50538336eab9914ac4524290f5b82fdb5565`.

## Первый этап — без системной маршрутизации

Сначала остановить другие копирования, установщики и старый SSH-прокси. При обнаружении действующего системного прокси/PAC помощник останавливается.

```bash
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/rescue/vless.sh -o /tmp/vless.sh
```

После успешного скачивания:

```bash
bash -n /tmp/vless.sh && bash /tmp/vless.sh prepare
```

Ссылка вводится в скрытый запрос, не отдельной командой оболочки. Альтернатива — одна строка URI в локальном UTF-8 файле `vless.txt` на установочной флешке (ничего не форматировать):

```bash
bash /tmp/vless.sh prepare /Volumes/Install*/vless.txt
```

При нескольких совпадениях используйте один точный путь в кавычках.

`prepare` временно поднимает mixed-прокси только на 127.0.0.1:2080 и делает HTTPS HEAD к www.apple.com через явно заданный SOCKS. Системные маршруты, DNS и прокси-настройки не изменяются. Тестовый процесс после проверки завершается. Ожидается `VLESS_TEST_OK`. Проверка одного адреса не доказывает доступность установочных пакетов, пригодность TUN или стабильность железа.

## TUN — отдельное подтверждение после успешной проверки

```bash
bash /tmp/vless.sh start
```

Нужно ввести `TUN`. sing-box создаёт utun19, маршруты IPv4/IPv6 и native DNS. Существующий utun19 не заменяется. Исходящие соединения клиента привязаны к исходному интерфейсу en* для предотвращения петли. Перед `TUN_READY` проверяются два контрольных маршрута и один IPv4 HTTPS-запрос. При сбое запуска клиенту посылается TERM; принудительного сброса маршрутов нет.

Режим предназначен для интернет-трафика TCP/UDP, **не абсолютно каждого IP-пакета**. Специфичные/локальные маршруты, bootstrap DNS и управляющее соединение к серверу — исключения. DNS приложений обрабатывается DNS-модулем и DoH через VLESS; DNS самого сервера использует заранее выбранный текущий IPv4 resolver напрямую. Нет списка только Apple, правил pf, kill switch, изменений T2/SIP, ремонта/стирания дисков.

Клиент уходит в фон и игнорирует обычный HUP терминала. Нет фонового цикла повторной записи настроек scutil. Работа рассчитана только на текущую сессию Recovery: перезагрузка, смена среды или полное зависание прервут туннель. Нет постоянной службы для экрана глобуса или автоматического перезапуска клиента. Это не исправляет причину аппаратного отключения/зависания.

```bash
bash /tmp/vless.sh status
bash /tmp/vless.sh stop
```

Остановка отправляет TERM процессу с проверенным путём нашего клиента. Уборка маршрутов/DNS делегируется штатному завершению sing-box. Если utun19 остался, выводится ошибка, чужие интерфейсы не удаляются. После завершения/аварии прямой доступ может возобновиться — **это не kill switch**.

Приватные настройки и журналы: `/private/tmp/recovery-vless` (права 700). JSON содержит UUID, права 600. Каталог целиком и конфигурации не публикуйте. При STOP показывайте только названный диагностический журнал.

## Что реально проверено

20 unit-тестов на Linux/Bash: синтаксис, разбор URI, percent-encoding, отклонение некорректного ввода, отсутствие печати UUID, синтаксическая корректность JSON, разделение probe/tun, проверки PID, системного прокси и исходного интерфейса. Один тест включает 18 отрицательных вариантов URI. В проверке JSON вызов sing-box check заменён заглушкой — это **не проверка схемы реальным sing-box**. Реальный сервер, legacy-клиент, фоновые процессы на macOS, маршруты/DNS и TUN интеграционно не тестировались. При `STOP` проверки не обходить.
