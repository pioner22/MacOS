# Аудит MacBook Diagnostics — 0.2.0-audit

Дата: 2026-09-19. Проверенный исходный срез: `pioner22/MacOS@9a10de61041d7d9dd87abecd01eba7e5c24f12a7`.
Область: диагностические shell/Perl/Metal-модули и их загрузчики. Yagodka/Electron-клиент, сторонние установщики macOS и вся плата ноутбука этим аудитом не проверялись.

**Статус: экспериментальная исправленная ревизия, НЕ коммерческий релиз.** Изменения предназначены для отдельной review-ветки, а не для незаметной замены выполняющегося теста.

## Что означают прежние ошибки RAM

Скриншоты показывают, что тест сообщил о несовпадениях. Это серьёзный диагностический сигнал, **но не независимое подтверждение дефекта определённого DRAM-чипа**. Восемь чтений одного буфера могут обслуживаться CPU-кэшем. `logical_test_page` и смещения 3080/3336 — координаты тестовой аллокации, а не физические адреса или выводы микросхемы. Равные счётчики 775 в разных проходах сами по себе не доказывают совпадение физических страниц.

Нельзя по этим данным заключать, что виноваты конкретный data lane, BGA или IMC. Нельзя и утверждать обратное — что ноутбук исправен или что все несовпадения созданы скриптом. Найденные ошибки downloader объясняют возможные ложные download FAIL, но не доказаны как причина RAM-событий. Дорогостоящая перепайка требует независимого теста и диагностики платы.

Новая C-реализация не использует Perl для хранения/сравнения тестового массива. Успешный `mlock` фиксируется; при его неудаче выводится ограничение покрытия. Даже mlock не обеспечивает доступ ко всей DRAM, физическую локализацию, исключение CPU-кэша или тест скрытой памяти firmware/T2. Ошибка сверки называется нарушением проверяемого data path, а не автоматически неисправной RAM.

## Что реально проверено здесь

В Linux x86-64 среде выполнены **47 регрессионных тестов**, включая компиляцию C с `-Wall -Wextra -Werror`, простые/адресные/walking паттерны, намеренно внесённый битовый дефект, отмену, исключение устройств `/dev` из file-test, сохранение пользовательского файла, контроль completion marker, синтаксис активного Bash/Perl-пакета, локальный HTTPS, обрыв, неправильный хэш, короткий ответ, 404, Range 206 и неправильный Content-Range.

SHA-256 всех пяти сетевых размеров и диапазона 16 MiB **заново вычислены** из генератора SHAKE-256. Это не означает, что GitHub Release assets опубликованы или скачаны из сети пользователя.

Отдельно выполнены AddressSanitizer + UndefinedBehaviorSanitizer: RAM 16 MiB, два quick-прохода; file-I/O 16 MiB, два чтения. Ошибок санитайзеров не зарегистрировано. Тесты не запускались на ноутбуке пользователя, не проверяли его SSD и не воспроизводили физическое отключение питания.

**Не подтверждено в этой среде:** macOS/Bash 3.2 runtime, Recovery, Metal compilation/runtime, T2, реальные 8–48 GiB RAM, полное логическое пространство SSD, перезагрузка/обесточивание, GPU/display hardware. Для этого добавлена CI-матрица Linux + macOS Intel, но наличие workflow не равно успешному CI. Требуется отдельный запуск и проверка результатов.

## Архитектура и безопасная политика

Загрузчик → один проверенный snapshot → явный выбор операции → preflight ресурсов → backend → наблюдения → ограниченный итог → рекомендации.

Основные подсистемы:

- `diagnostics/core.sh`: пути, состояния, подтверждение, SHA self-check.
- `diagnostics/run.sh`: оркестрация и запрет зависимых проверок после RAM FAIL/INCONCLUSIVE.
- `diagnostics/net.sh`: отдельные параметры каждого повтора, HTTP/size/SHA/Range.
- `diagnostics/ram_native.c`: независимая нативная сверка; `ram_fallback.pl`: скрининг Recovery.
- `diagnostics/storage_file.c`: только собственный новый файл, не весь диск; кеширование/flush имеют явные ограничения.
- `diagnostics/metal_vram.m`: ограниченный Metal data-path smoke test; shared readback зависит и от основной RAM.

Предыдущий destructive full-LBA workflow намеренно не продолжается этой ревизией. Сохранённый Pattern A не форматируется и не перезаписывается. Весь старый код доступен в истории Git, но не входит в активный исполняемый пакет. Новый пункт Storage означает file-test, а НЕ полное сканирование/перезапись накопителя.

## Перед коммерческим выпуском

1. **Валидация диагностики:** независимый эталонный тест, заведомо исправные и неисправные платы, fault injection; оценка ложных PASS/FAIL. Результат теста и аппаратная причина — разные поля отчёта.
2. **Безопасный RAW backend:** выбор по устойчивой идентичности, связь APFS-volume/container/physical store, исключение системного/резервного носителя, проверка unmount, явное подтверждение каждого опасного действия, сохранение журналов и проверка restart/checkpoint на эмуляторе диска. До этого RAW заблокирован.
3. **Ограничения ресурсов и процессов:** доступная память, memory pressure, питание, monotonic timers, supervisor всей группы дочерних процессов, обработка аварий/тепловых ограничений. Нынешний процент установленной RAM не гарантирует отсутствие OOM при занятости системы.
4. **Выпуск и доверие:** подписанные x86_64/arm64 бинарники, Developer ID/notarization, подписанный неизменяемый манифест, проверка обновления и отката; offline-пакет для Recovery без необходимости компилятора. SHA-256 и HTTPS не равны подписи производителя.
5. **Сведения и приватность:** журнал событий/JSON со схемой, версии всех движков, идентификатор запуска, реальные байты/покрытие, сохранённые артефакты, redaction серийных номеров; загрузка логов только с согласия. Не обещать переживание внезапного выключения без проверенного fsync-протокола.
6. **Лицензирование:** в исходном репозитории GPLv3. Продажа GPL-продукта допустима при выполнении условий. Закрытая/двойная лицензия требует проверки происхождения кода и прав всех правообладателей; ранее выданные GPL-права не исчезают. Лицензия этим аудитом не менялась.

Проверка соответствия ГОСТ, сертификация, гарантия ремонта и готовность к эксплуатации коммерческого ПО этим аудитом не заявляются.
