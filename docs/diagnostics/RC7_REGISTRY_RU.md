# Реестр совместимости — 2.0.0-rc7 / Bootstrap 1.4

## Что изменено

Реестр подключён к действующему diagnostics_v2, а не поставлен как второе неподключённое меню. Обычный st.sh проверяет единый пакет, определяет фактическую среду, выполняет небольшие пробы, разрешает профиль и только затем показывает меню. Нагрузка не запускается при выборе профиля. Существующие номера сохранены; пункт 21 показывает паспорт возможностей и план без аппаратной нагрузки. Один выбранный тест/комплекс → финальный отчёт → выход; пункт 15 возвращает в меню. Новый запуск — новый сеанс, не автоматическое повторение нагрузки.

На машине не нужны Python, JSON::PP, jq, Homebrew или установленная macOS только ради реестра. Авторские данные registry/diagnostics.json преобразуются разработчиком в четыре небольших TSV. TSV не исполняются и не подключаются через source/eval. Фиксированные адаптеры находятся в registry.sh. Полная диагностика по-прежнему требует тех инструментов, которые использует конкретный движок.

## Данные и происхождение

13 документальных записей для 11 Model Identifier взяты из уже существующего macdiag_core/registry/catalog.json (исходный blob и commit указаны в JSON). Это экспорт справочных данных, не подключение Perl-ядра macdiag_core. Его CLI и VPN не изменены. Для MacBookPro11,2 и 11,3 показываются два кандидата года, а не выдуманный единственный год. Ни одна запись не означает аппаратную валидацию. Неизвестные модели не получают вымышленных характеристик; общий Intel/Apple Silicon профиль зависит от реально обнаруженного CPU.

Девять приоритетных шаблонов сопоставляют семейство железа, среду, ОС, точную сборку и семейство Bash. Равный приоритет двух подходящих правил означает неоднозначность и ограниченный режим. Ручные Limited/Other не повышают права профиля. Точные запреты для новых сборок можно добавить отдельным более приоритетным правилом; список таких известных дефектов не выдумывается заранее.

12 контрактов инструментов/возможностей: исполняющий Bash, системный Bash, curl, Perl, модули супервизора, модули безопасного файла, 64-битные смещения, SHA-256, diskutil plist, кандидат компилятора, awk TSV, tee -i. Bash измеряется отдельно от года Mac и оболочки интерактивного терминала. Общий код использует подмножество Bash 3.2, а не копию каждого теста для каждой версии. Фактическая macOS/Bash 3.2 здесь ещё не испытана.

Состояния возможностей: MISSING, UNUSABLE, VERIFIED, CANDIDATE. VERIFIED относится только к указанной пробе; это не проверка всего инструмента и не аппаратный PASS. Компилятор остаётся CANDIDATE до настоящей сборки теста. Проба curl проверяет поддержку HTTPS и используемых параметров без запроса в сеть. Отличие --max-filesize до/после 8.4 записано как ожидаемое по документации; независимый счётчик байтов и предел загрузчика сохраняются в обоих случаях. SHA проверяется известным ответом, Perl — необходимыми модулями и pack/разрядностью, awk — пустыми TAB-полями и большими числами. diskutil probe корневого plist не устанавливает идентичность целевого диска: она перепроверяется отдельно перед чтением/записью.

## Исполнение

Диспетчер фиксирует этап, выбранный backend, состояние READY/LIMITED/UNAVAILABLE/BLOCKED и причину. READY означает только выполнение предварительных требований. Перед аппаратным этапом сохраняются существующие mlock, бюджет памяти, проверка тома, права и отдельное подтверждение записи. Новых автоматических нагрузок нет. Переключение на слабую проверку после уже найденной ошибки запрещено. Отсутствие подходящего движка не становится аппаратным FAIL.

Без компилятора Recovery выбирает только ограниченный Perl-screen. RAM MAP без native недоступен. Полные native нагрузки остаются ограничены совместимой Intel-средой и обязательным mlock; проверенные готовые native binaries для Recovery этот выпуск не добавляет. Apple silicon не получает Intel-движок по архитектуре x86_64 процесса Rosetta. RAW 1/13 заблокированы. Пункт 20 остаётся только чтением и требует работающих модулей, 64-битных смещений, подходящего профиля, метаданных и согласия. Сеть после явного выбора может проверяться без Perl, когда достаточно curl; DOWNLOAD требует также SHA/Perl/supervisor.

## Журналы и обратная связь

До меню сохраняются profile.txt, environment.tsv и дополнительные tool-capabilities.tsv, registry-selection.txt, registry-hashes.tsv, registry-meta.tsv, dispatch-plan.tsv. Метаданные включают версию, профиль, точную работающую ОС/build и ревизию кода. Отчёт отличает план от фактического результата. Пути инструментов и все сырые журналы — приватные данные; автоматической отправки нет. SUPPORT не копирует сырые capability logs без просмотра. Для воспроизведения сложного сбоя их можно передать отдельно после проверки на приватные сведения.

## Включённый предыдущий lifecycle-патч

В rc6 уже существовал локально проверенный, но неопубликованный кандидат: остановка Recovery-плана после неполного RAM/CPU; запрет дальнейшей нагрузки после тайм-аута запущенного GPU; проверка rc sysctl при подсчёте CPU; единственный FINAL_STATE после сохранения отчёта; запрет устаревшего текста PASS после сбоя процесса; честная подсказка при отмене read-only до запуска. Он включён в этот единый выпуск, не потерян при добавлении реестра. Критерии приёмки не ослаблены.

## Воспроизводимость и тестирование

Авторские таблицы: python3 tools/build_diagnostics_registry.py --check.
При обновлении общих данных устройств: python3 tools/build_diagnostics_registry.py --core-catalog macdiag_core/registry/catalog.json, затем указать реально проверенный source commit и review diff. Генерация таблиц сама по себе не обновляет опубликованный descriptor.
Полный набор: python3 -m unittest discover -s tests/diagnostics_v2 -v.
Вспомогательные модели старых unit-тестов отделены от новых интеграционных проверок реестра: там mock capability provider явно оставлен legacy. Новые тесты реально исполняют TSV parser, Bash, SHA/Perl/awk/tee/curl-option probes на Linux; факты Mac и специальные отказы контролируемо имитируются. Количество, выводы и ограничения финального прогона записаны в QA rc7, а не выводятся из числа файлов.

Выпуск не доказывает полноту базы всех устройств/сборок; не содержит собственного сервера логов, подписи независимого источника или полной офлайн-карты всех инструментов. SHA фиксирует целостность относительно доверенного загрузчика, не его подлинность. Очистка BASH_ENV для дочерних запусков не отменяет код, уже выполненный начальной внешней оболочкой. Конфигурация CI для Mac — не результат её исполнения.
