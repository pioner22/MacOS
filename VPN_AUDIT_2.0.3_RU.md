# BigSurVPN 2.0.3: права каталогов и интерфейс команд

Дата отчёта: 21 сентября 2026 года. Это точечное исправление версии 2.0.2, не полный аудит VPN и не подтверждение работы на конкретном Mac.

## Причина и исправление

`umask 077` превращал запрошенный режим `mkdir(..., 0755)` в `0700`. Это затрагивало `/Library/BigSurVPN`, `releases` и создаваемый `/usr/local/bin`. Даже исполняемый командный файл внутри закрытого каталога был недоступен обычному пользователю.

В `prepare_dirs` после проверки владельца, типа, режимов и приватных файлов явно выставляются `private=0700`, `releases=0755`, `BigSurVPN=0755`. Приватное состояние проверяется до открытия внешнего каталога. Глобальная маска `077` не ослабляется. Содержимое профилей не меняется этой операцией; новые приватные файлы по-прежнему записываются с режимом `0600`, оболочка команды — `0755`.

Новый `prepare_command_dir` создаёт отсутствующие общие каталоги с последующим явным восстановлением `0755`; существующие root-каталоги с режимом `0700` исправляются. Доступные безопасные режимы, например `0711`, не меняются. Символические ссылки, чужие владельцы, запись для группы/остальных и неожиданные недоступные режимы приводят к отказу. Каталоги Homebrew, принадлежащие пользователю, не присваиваются root и не исправляются автоматически: такая установка остановится на проверке. Проверка пути команды выполняется до скачивания ядра и остановки работающего VPN, затем повторяется при активации.

## Команды

Сохранены `status`, `test`, `on`, `off`, `speed`, `list`, `select N`, `update`, `report`, `logs`, `uninstall`. Добавлены формы `--status`, `--test` и аналогичные варианты с двумя дефисами. Без аргументов выполняется `status`.

`help`, `--help`, `-h` и `version`, `--version`, `-V` работают без sudo. Оболочка выводит их сама, без обращения к приватным данным или запуску Python. Ошибочная команда и неверное количество аргументов отклоняются до повышения привилегий с кодом 2. Команды управления по-прежнему требуют административных прав. `update` обновляет подписку серверов, а не программу.

## Закреплённые исходники

Исходная ветка: `main` на `59123222ce4148c6464a3c0dbc019ac5938ddbe1`.
Ветка исправления: `fix/vpn-2.0.3-permissions-cli`.

В `vpn.sh` закреплён runtime из коммита `ba550cbd6f96ac7cd9efb2208d218ed1837c1692`:

```text
SHA-256: 0be06b6023c4ddbb808563af357cbef563f6dd97b54f20bc69bf05d0b02a097e
Git blob: 75d51defcbe8d04582f54e5251ebe7bcb60b78b3
```

Git blob опубликованного runtime и загрузчика совпали с локальными копиями. Закрепление и SHA-256 файла профиля сохранены. Профиль, учётные данные, версия sing-box, сетевые алгоритмы, временный DNS и маршруты в этом изменении не обновляются. Сравнение синтаксических деревьев исходной и новой версии показало 61 неизменённую функцию/класс; из существующих изменены только `prepare_dirs`, `activate_install`, `setup`, `main`.

## Проверки и границы доказательств

Локально выполнены **51 тест, 51 успешный, без пропусков**: Linux, Python 3, Bash среды проверки. Тесты используют временные каталоги; проверки доступа запускают дочерние процессы с непривилегированным UID. VPN, launchd и реальные сетевые соединения тестами не запускаются.

Проверены воспроизведение `0700`, восстановление доступа к команде, сохранение недоступности приватных данных, повторное применение, пять масок umask, отказ при небезопасных владельцах/ссылках/жёстких ссылках/правах, разбор команд и границы аргументов, справка/версия без sudo, сохранение административной ветки управления и проверка путей до остановки службы. Отдельно успешно выполнен `bash -n vpn.sh`, проверены соответствие SHA-256 runtime закреплению в загрузчике и неизменность закрепления профиля.

```sh
python3 -m unittest discover -s tests -p 'test_vpn_permissions_cli.py' -v
```

Для полного набора проверок прав доступа к файлам требуется root в изолированной тестовой среде; без root соответствующие тесты будут пропущены. Это не результат полного набора тестов репозитория или GitHub Actions.

**Не проверено:** настоящая macOS Big Sur, штатные Python 2.7 и Bash 3.2, ACL macOS, установка на устройстве владельца, подключение к серверу, смена IP и DNS после обновления. Успех локальных тестов не заменяет эти проверки.

## Обновление установленной копии

Ранее предложенный блок chmod восстанавливает доступ к установленной 2.0.2 без перезапуска VPN, но не обновляет код и не добавляет новые команды. В 2.0.2 после такого исправления нужно использовать `vpn-bigsur status`, а не `--status`.

Полное обновление через `vpn.sh` до 2.0.3 скачивает и проверяет код/ядро, затем останавливает собственный VPN и подключается заново. На промежутке возможен прямой интернет: kill switch не добавлен. Не следует переустанавливать работающий VPN только ради немедленного исправления прав, если разрыв соединения недопустим.

До слияния ветки исправления в main обычная ссылка `/main/vpn.sh` продолжает устанавливать старую закреплённую версию. После установки 2.0.3 проверить без sudo перед командой:

```sh
hash -r
/usr/local/bin/vpn-bigsur --version
/usr/local/bin/vpn-bigsur --help
/usr/local/bin/vpn-bigsur --status
```

Ожидаемая версия: `BigSurVPN 2.0.3`. Справка и версия не спрашивают пароль; состояние может запросить административные права. Само сообщение о версии не доказывает работу туннеля: для этого служит отдельный `vpn-bigsur test`.
