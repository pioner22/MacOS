# Catalina через VLESS на втором Intel Mac — 1.0.0

Основной запуск: `download-vpn.sh`. Для A1398 с обычной macOS Big Sur, НЕ для Recovery на A2141. Прежние `proxy.sh` и `vless.sh` одновременно не запускать. Используется подключение VLESS + REALITY + XTLS Vision из личной ссылки, а не прежний SSH-сервер.

## Запуск без sudo

```bash
/usr/bin/curl -q -fL --proto '=https' --proto-redir '=https' --connect-timeout 20 --max-time 120 \
  https://raw.githubusercontent.com/pioner22/MacOS/rescue/download-vpn.sh \
  -o "$HOME/download-vpn.sh" \
  && /bin/bash -n "$HOME/download-vpn.sh" \
  && /bin/bash "$HOME/download-vpn.sh"
```

В запрос `VLESS URI:` вставьте свою полную ссылку и нажмите Enter. Ввод скрыт. Не передавайте URI аргументом командной строки. Для чтения из локального файла:

```bash
/bin/bash "$HOME/download-vpn.sh" --uri-file "$HOME/Downloads/vless-private.txt"
```

Ссылка сохраняется только локально в `~/macOS-rescue/.vless-client/profile.uri`, права 600; каталог имеет права 700. Это ограничение доступа, не шифрование. В GitHub личные UUID, ссылки и пароли не включены. Повторный запуск использует сохранённый профиль. Для его замены добавьте `--reconfigure`. Параметр `spx/spiderX` не переносится в несуществующее поле sing-box; программа сообщает об этом и проверяет реальное соединение.

## Порядок работы

Проверяются системные программы. В пользовательский каталог скачивается официальный sing-box 1.14.0 `darwin-amd64-legacy-macos-10.13`, около 26 МБ; SHA-256 сверяется с метаданными релиза. Затем проверяются `version` и конфигурация клиента. Загрузчик Catalina 1.1.0 скачивается по фиксированному коммиту и также сверяется с SHA-256.

Клиент открывает только localhost HTTP/SOCKS-прокси на свободном порту 2080–2090. Сначала выполняется HTTPS HEAD к www.apple.com через VLESS. Только при успехе запускается загрузчик InstallESDDmg.pkg. Он проверяет размер, получает файл с ограниченными повторами и дозагрузкой, вычисляет SHA-256 и запускает проверку фактического формата PKG/DMG. Файл не исполняется и образ не монтируется.

В старом загрузчике `-x ''` выключал прокси. В версии 1.1.0 явный `--socks5 127.0.0.1:PORT` переключает HEAD и GET на SOCKS5h с `--noproxy ''`. При отказе этого подключения прямого fallback нет. В конфигурации клиента нет direct-выхода.

**Это не VPN всего компьютера.** Системные DNS, маршруты, hosts и прокси-настройки не меняются; TUN, firewall, launchd, Homebrew и sudo не используются. Шифрованный транспорт используется только для теста и загрузки через локальный прокси. Другие программы не охватываются, системного kill switch нет. Первоначальная загрузка клиента/скрипта с GitHub и разрешение имени VPN-сервера используют обычное соединение.

Если GitHub недоступен, оригинальный архив клиента можно перенести с другого устройства и передать `--core-archive /абсолютный/путь/архив.tar.gz`; SHA-256 останется обязательным. Доступ к raw.githubusercontent.com для закреплённого загрузчика также необходим. Не отключайте проверки сертификатов или хеша.

## Ожидаемые результаты

```text
VLESS_TEST: curl=0 HTTP=200
VLESS_TEST_OK: ...
TRANSPORT=SOCKS5H ENDPOINT=127.0.0.1:2080 DIRECT_FALLBACK=DISABLED
HEAD_CURL_EXIT=0
...
DOWNLOAD_OK: ...
READY_FOR_REVIEW: ...
DOWNLOADER_EXIT=0
```

Порт может отличаться. Тест сайта не подтверждает доступность пакета. READY_FOR_REVIEW означает, что передача и соответствующая команда проверки прошли; отчёт проверки нужно просмотреть. Самостоятельно вычисленный SHA-256 без доверенного эталона не доказывает подлинность. Проверка DMG не подтверждает подписи всех внутренних пакетов или статус отзыва сертификатов.

Пакет и отчёты сохраняются в новом каталоге:

```text
~/macOS-rescue/Catalina-001-68446-VLESS/
```

До завершения передачи файл имеет окончание `.part`. Предыдущая прямая загрузка не удаляется и не импортируется. При повторном запуске этого же VPN-загрузчика проверяется возможность продолжения из нового каталога:

```bash
/bin/bash "$HOME/download-vpn.sh"
```

Не больше трёх GET-попыток за запуск; проверяются Range и ETag/Last-Modified. Два часа на одну попытку; 120 секунд со скоростью менее 1 КиБ/с останавливают запрос. Ошибки подписи, неизвестный формат и изменение удалённого файла не обходятся. Для независимой новой попытки предусмотрен `--output /абсолютный/путь`.

Используется HTTPS-вариант пути продукта 001-68446, хотя исходный установщик обращался по HTTP. Успех не доказывает работоспособность исходного HTTP-запроса. Этот шаг не поднимает локальное зеркало и не создаёт флешку.

## Сон, остановка и журнал

Держите A1398 на питании, крышку открытой и Терминал открытым. `caffeinate` предотвращает автоматический сон на время работы. Клиент работает фоновым дочерним процессом, но постоянного демона нет. Это не защита от аппаратного зависания.

Ctrl+C останавливает запуск, частичный пакет и отчёты сохраняются. При обычном завершении или ошибке клиенту отправляется TERM. Если он не завершается, выводится предупреждение; SIGKILL не используется. Приватный профиль и архив остаются для повторного запуска. Каталог `~/macOS-rescue/.vless-client` целиком не публикуйте: там есть личная ссылка и JSON.

SHA-256 архива: `99285bb2d30739dc8884144cf90f50538336eab9914ac4524290f5b82fdb5565`.
Коммит загрузчика: `fcf65e639269e1259c64d8aa46a43bd63da134c7`.
SHA-256 загрузчика: `2e86bca5dc16d594ff70afb3e7bfed5a6f65b0e167e0c64e8de88798c08fb7de`.

Пройдено 49 локальных тестов Linux: 29 регрессионных и 20 новых. В том числе настоящие HTTPS HEAD/GET через тестовый SOCKS5 с проверкой TLS и передачей имени серверу SOCKS; обрыв/дозагрузка; отсутствие прямого fallback при выключенном прокси. Проверены разбор URI, отсутствие личных значений в выводе и JSON с одним VLESS-выходом. В тесте генерации `sing-box check` заменён заглушкой. pkgutil/hdiutil моделировались, BSD stat заменён GNU stat. Bash 3.2 на macOS непосредственно не запускался.

**Реальный клиент на Big Sur, VLESS/REALITY-сеанс, lsof/caffeinate на Mac и скачивание реального пакета Apple здесь НЕ проверены.** Попытка скачать бинарный архив в вычислительной среде остановилась на DNS с curl exit 6. Доступность метаданных через GitHub-коннектор не доказывает доступность бинарного файла из любой сети.
