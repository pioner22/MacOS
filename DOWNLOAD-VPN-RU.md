# Catalina через VLESS на втором Intel Mac — 1.1.0

`download-vpn.sh` предназначен для A1398 с обычной macOS Big Sur, **не для Recovery на A2141**. Старые `proxy.sh` и `vless.sh` одновременно не запускать. Это VLESS + REALITY + XTLS Vision, а не прежнее SSH-подключение.

## Короткий запуск

На A1398, без sudo, после завершения или остановки предыдущего запуска:

```bash
curl -qfLo ~/v.sh https://raw.githubusercontent.com/pioner22/MacOS/rescue/download-vpn.sh && bash ~/v.sh --reconfigure
```

На запрос:

```text
VPN link (vless:// or https://):
```

вставьте полную личную ссылку и нажмите Enter. Ввод скрыт. `--reconfigure` нужен, чтобы запросить новую ссылку вместо ранее сохранённого профиля. Не передавайте ссылку аргументом командной строки и не выполняйте содержимое подписки через bash.

Для последующих запусков:

```bash
bash ~/v.sh
```

Для файла, содержащего одну строку vless:// или HTTPS-ссылку подписки:

```bash
bash ~/v.sh --uri-file "$HOME/Downloads/vpn-link.txt"
```

## Импорт подписки

Теперь поддерживается HTTPS-ссылка, возвращающая обычный список URI либо Base64-кодированный список (стандартный или URL-safe Base64). Поддерживаются CRLF, UTF-8 BOM и отсутствие завершающего Base64 padding. HTML-страницы, JSON/Xray и YAML/Clash конфигурации не импортируются.

Из списка выбираются только профили, которые уже поддерживал наш клиент: VLESS / REALITY / xtls-rprx-vision / TCP / encryption=none / fp=chrome. Если найден один подходящий профиль, он выбирается автоматически; при нескольких скрипт показывает нумерованный список серверов и просит номер. Секреты и произвольные названия профилей не выводятся. Неподдерживаемые записи учитываются отдельно; нет скрытого преобразования других протоколов.

Можно явно выбрать номер среди поддерживаемых профилей:

```bash
bash ~/v.sh --profile-index 2
```

Параметр `spx/spiderX` не переносится в выдуманное поле sing-box; скрипт сообщает об этом. Работоспособность соединения проверяется реально на компьютере пользователя.

Запрос подписки выполняется **до включения VLESS через обычное соединение**. HTTPS-сертификат проверяется, автоматическое следование перенаправлениям отключено. Токен передаётся curl через stdin-конфигурацию, не через аргументы процесса. При 301/302/403, HTML или неподдерживаемом формате скрипт останавливается. Ограничения: 60 секунд, до 1 МиБ ответа и до 128 записей. Помимо `--max-filesize`, используется ограничение размера создаваемого файла для старых curl.

При сохранённой HTTPS-ссылке подписка запрашивается заново при следующем запуске. При нескольких профилях выбор может потребоваться повторно.

## Приватные данные

Ссылка сохраняется только локально: `~/macOS-rescue/.vless-client/profile.uri`, права 600, каталог 700. Это ограничение доступа, не шифрование. JSON выбранного клиента также содержит секреты и имеет права 600. Исходный и декодированный ответы подписки удаляются при штатном завершении или обработанном сигнале. Аварийное выключение может оставить их в приватном каталоге.

Заголовки и stderr запросов могут содержать чувствительные сведения. Каталог `.vless-client` целиком не публикуйте. В публичном GitHub нет персональной ссылки, UUID, токена подписки или пароля.

## Подключение и загрузка

После импорта профиля скрипт получает официальный sing-box 1.14.0 `darwin-amd64-legacy-macos-10.13` (около 26 МБ), сверяет SHA-256 и запускает `version` / `check`. Затем получает закреплённую версию `download-catalina.sh` 1.1.0 и сверяет её SHA-256. Не обновляет Homebrew, Python или macOS.

Клиент слушает только localhost на одном свободном порту 2080–2090. Системные маршруты, DNS, hosts и параметры прокси не меняются. TUN, firewall, launchd и sudo не используются. **Это не VPN всего компьютера.** Через VLESS направляются тестовый запрос и HEAD/GET самого загрузчика; для них прямого fallback нет. Запросы подписки, GitHub и разрешение адреса VLESS-сервера используют обычную сеть. Системные проверки доверия, выполняемые сторонними утилитами после скачивания, не получают гарантию маршрутизации через этот прокси.

Проверочный HEAD к `www.apple.com` должен пройти до загрузки большого пакета. Он не доказывает доступность самого пакета.

```text
SUBSCRIPTION_FETCH: curl=0 HTTP=200
SUBSCRIPTION_FORMAT=BASE64_LINKS
SUBSCRIPTION_PROFILES=1 UNSUPPORTED_RECORDS=0
SELECTED_PROFILE=1
...
VLESS_TEST_OK: ...
TRANSPORT=SOCKS5H ENDPOINT=127.0.0.1:2080 DIRECT_FALLBACK=DISABLED
HEAD_CURL_EXIT=0
...
DOWNLOAD_OK: ...
READY_FOR_REVIEW: ...
DOWNLOADER_EXIT=0
```

Количество профилей и порт могут отличаться. После успешной проверки начинается получение `InstallESDDmg.pkg` продукта `001-68446` по HTTPS-варианту пути из журнала. Исходный установщик использовал HTTP; успех нашего HTTPS-запроса не доказывает исправность исходного HTTP-запроса.

Результаты: `~/macOS-rescue/Catalina-001-68446-VLESS/`. Частичный файл оканчивается на `.part`; предыдущая прямая загрузка не удаляется и не импортируется. В одном запуске не более трёх GET-попыток; дозагрузка разрешена при согласованных Range и ETag/Last-Modified. До двух часов на попытку; 120 секунд со скоростью менее 1 КиБ/с останавливают запрос. Ошибки сертификатов, изменившиеся данные и аварии не обходятся.

После передачи проверяются размер, собственный SHA-256 и фактический формат. Для XAR/PKG используется `pkgutil --check-signature`, для UDIF/DMG — `hdiutil verify`. Пакет не исполняется, образ не монтируется. READY_FOR_REVIEW означает успех предусмотренных команд, не гарантию установки: просмотрите отчёт. Собственный SHA-256 без доверенного эталона не доказывает подлинность. Проверка DMG не проверяет все внутренние подписи и отзыв сертификатов.

## Сон и остановка

Терминал и крышку A1398 держать открытыми, питание подключить. `caffeinate` предотвращает автоматический сон на время скрипта. Ctrl+C останавливает запуск с сохранением частичного пакета; своему клиенту отправляется TERM. Нет постоянного демона, автозапуска при включении или защиты от аппаратного зависания.

## Зависимости и фактические проверки

Версия клиента и закреплённый загрузчик не изменены относительно 1.0.0:

- Метаданные клиента: https://api.github.com/repos/SagerNet/sing-box/releases/assets/537409689
- SHA-256 архива: `99285bb2d30739dc8884144cf90f50538336eab9914ac4524290f5b82fdb5565`
- Коммит загрузчика: `fcf65e639269e1259c64d8aa46a43bd63da134c7`
- SHA-256 загрузчика: `2e86bca5dc16d594ff70afb3e7bfed5a6f65b0e167e0c64e8de88798c08fb7de`

На Linux выполнены **79 тестов**: прежние 49 и 30 новых. Новые проверки включают настоящую локальную HTTPS-выдачу подписки с проверкой TLS, отказ недоверенному сертификату, запрет redirect, HTTP-ошибки, Base64/raw, выбор профиля, отсутствие токена в аргументах curl, ограничения размера и отказ импорта конфигураций/управляющих байтов. Регрессионные проверки включают HTTPS через тестовый SOCKS5, обрыв/дозагрузку и отсутствие прямого fallback.

BSD stat адаптирован к GNU stat; системные проверки pkgutil/hdiutil и `sing-box check` моделируются. **Реальный sing-box/VLESS-сеанс, запуск всей связки на Big Sur и полная загрузка пакета Apple здесь не тестировались.** Попытка получить настоящую подписку из вычислительной среды остановилась на DNS до HTTP-ответа; содержимое и доступность пользовательской подписки не подтверждены. Тесты проверяют поддерживаемые форматы на синтетических примерах, не работу конкретного сервиса.
