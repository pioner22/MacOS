# Compatibility registry — 2.0.0-rc7 / Bootstrap 1.4

The registry is integrated into diagnostics_v2 before the menu. It does not replace the separate macdiag_core CLI or change VPN. Thirteen documentary device entries (eleven identifiers) are exported from the existing core catalog, preserving ambiguous introduction years. Device year never selects Bash. Nine prioritized profile templates support hardware, environment, OS, exact build and Bash-family constraints. Tied rules fail closed; manual choices can restrict, not elevate.

Build-time JSON compiles into four bounded TSV files; runtime uses a Bash 3.2-compatible library with fixed adapters, no JSON parser/Python/jq requirement and no eval. Twelve tool/capability contracts distinguish running/system Bash, HTTPS option parsing, Perl/modules/64-bit offsets, known-answer SHA, root diskutil plist, toolchain candidate, awk parsing and tee's option. Version-derived curl size-limit behavior is labeled expected, not tested. External byte limits remain. Candidate compiler is not proof of build success; native mlock/resource/target checks still run at the actual stage.

The live plan is saved before the menu, displayed and checked at dispatch. READY is not PASS; LIMITED is not whole-machine coverage. Unknown configurations never enable native stress. Perl screens remain limited; RAW stays blocked; read-only/storage/bridge consent is preserved. No new heavy workload or verified precompiled Recovery binary is included.

Option 21 or positional `profile` emits a capability passport/plan only. One menu selection runs one session, writes a final report and exits; profile editor 15 returns to the menu. Existing offline mode uses the same verified package. The earlier unpublished lifecycle fixes are included, with regression tests.

Local logs include tool-capabilities.tsv, registry-selection.txt, registry-hashes.tsv and dispatch-plan.tsv. They may contain sensitive paths and are not automatically uploaded. No arbitrary remediation code is downloaded on failure. To extend the catalog, add documented data/adapter contracts and regressions, then publish a reviewed immutable package. Programmatic validation, actual environment compatibility and hardware-diagnostic sensitivity are distinct evidence levels.

Full validation commands and exact final results are provided in the companion QA log. Linux probes/mocks do not establish real macOS/Recovery/Bash 3.2/Metal compatibility. Mac CI definitions do not themselves constitute Mac CI success. No whole-device certification is claimed.
