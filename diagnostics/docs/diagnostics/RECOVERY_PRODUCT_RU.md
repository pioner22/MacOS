# Recovery-first диагностика и обратная связь — проектирование и rc3

## Решение

Основной сценарий — Mac без установленной системы, Terminal внутри Recovery. Работа из обычной macOS сохраняется. Запуск: неизменная команда main/st.sh; минимальный preflight → проверка пакета → идентификация фактически работающей системы → проба инструментов → составной профиль → журнал профиля → меню → выбранный тест. Сам выбор профиля не запускает нагрузку.

Это развиваемый диагностический продукт, не сертификат исправности. Профессиональное качество означает воспроизводимость, минимальные права, сохранность данных, ограниченные выводы, явное покрытие и независимую проверку реализации. Название «Full» не даёт права скрывать, что часть памяти/VRAM/диска недоступна.

## Архитектура профилей

Не создавать по отдельной копии скрипта на каждое сочетание модели и ОС. Профиль составляется из независимых измерений:

1. Платформа и архитектура: Darwin / неизвестная; Intel / Apple silicon / неизвестно; архитектура процесса отдельно от CPU; Rosetta учитывается.
2. Оборудование: hw.model, RAM, страница памяти, CPU brand. A2141 выделен по двум Model Identifier. Наличие T2 по модели — ожидаемая конфигурация, не результат измерения T2.
3. Загруженная ОС: версия/сборка, не версия установщика и не ОС на соседнем томе. Распознавание High Sierra—Tahoe не означает испытанную совместимость всех тестов.
4. Среда: Recovery, полноценная macOS, safe mode, неоднозначная installer/recovery, unknown. CDIS + Base System используются как эвристические свидетельства; local/Internet Recovery надёжно не различаются. UID 0 не доказывает Recovery.
5. Консоль: tty, SSH, headless; фактический Bash, а не только $SHELL. Команда с pipe получает интерактивный ввод через /dev/tty. При headless нет молчаливого согласия на запись.
6. Возможности: рабочий Perl и необходимые модули, SHA с known-answer test, curl, кандидаты toolchain, доступность системных утилит. «Команда есть» и «команда работает» — разные состояния.

profiles.tsv содержит девять упорядоченных шаблонов, а не исполняемый код: A2141 Recovery/full, Intel Recovery/full, Apple Recovery/full, safe, installer-limited, unknown. Конкретный PROFILE_ID добавляет версию ОС, архитектуру процесса и тип консоли. Неизвестная модель не становится A2141 по ручному выбору. Unknown и ограниченный профиль не дают права на нативную большую нагрузку.

Текущий уровень доказательности профилей: SOFTWARE_TESTED_REAL_HARDWARE_PENDING. Дальнейшие уровни следует хранить отдельно для профиля, движка и объёма: implemented → simulated → real-environment-validated → release-approved. Ни число профилей, ни зелёный self-test не заменяют real-environment validation.

## Сценарии исполнения rc3

| Среда/возможности | RAM | Файловая проверка | CPU/сеть | GPU |
|---|---|---|---|---|
| Recovery + Perl, без компилятора | Ограниченный core-Perl screen | Новый файл 256 МиБ, два чтения | Уменьшенный SHA execution test; HTTPS/download при наличии зависимостей | Только сведения/ручная проверка |
| Recovery + рабочий совместимый toolchain | Кандидат native + обязательный mlock | Native, после явного выбора тома | Как разрешено возможностями | Не включается автоматически |
| Полная Intel macOS + toolchain | Native, память ограничена бюджетом vm_stat и mlock | Native-файл 1 ГиБ | Полный предусмотренный SHA execution test и сеть | Экспериментальный Metal |
| Полная macOS без toolchain | Ограниченный Perl screen | Ограниченный Perl file screen | По возможностям | Не выдаётся VRAM PASS |
| Apple silicon | Отдельный ограниченный профиль; пока Perl screen | Ограниченный screen | По возможностям | Нативная валидация впереди |
| Unknown / нет необходимых инструментов | Нагрузка недоступна | Нагрузка недоступна | Только доступные наблюдения/HTTPS | Не проверен |

Perl RAM: quick до 256 МиБ, extended до 1 ГиБ, не более 1/8 установленной RAM; шесть адресозависимых шаблонов. Это не полный тест 64 ГиБ, не обход компрессии/кэша и не физическая карта DRAM. Чистый скрининг даёт INCONCLUSIVE/RAM_SCREEN_CLEAN_NATIVE_PENDING с явным объяснением, а не ложный полный PASS. Несовпадение — FAIL проверяемого пути, не локализация чипа. Ctrl+C/TERM/HUP и timeouts сохраняют состояние незавершённости.

Native RAM и bridge сохраняют обязательный mlock. Для большой нагрузки дополнительно оценивается доступный бюджет по vm_stat с резервом. Это оценка, не гарантия отсутствия memory pressure: нагрузку сторонних приложений и изменение ресурсов между пробой и выделением нельзя исключить.

Perl file: только новый exclusive/no-follow файл, fsync, закрытие и два повторных чтения, сверка содержимого. Нет F_NOCACHE и доказательства холодного чтения NAND, поэтому чистый результат остаётся INCONCLUSIVE/FILE_SCREEN_CLEAN_CACHE_UNPROVEN. В Recovery нельзя по Enter начать запись в /var/root: нужен существующий каталог под /Volumes и согласие TEST-FILES. Том не форматируется и не создаётся. При mismatch собственный тестовый файл сохраняется.

**Критическое следующее расширение:** готовые нативные x86_64/arm64 бинарники для соответствующих минимальных macOS/recoveryOS, собранные на macOS, проверенные по ABI/dylib/min OS, размеру/хэшу и подписи. Нужен небольшой smoke-test перед большой нагрузкой. Сейчас таких проверенных бинарников rc3 не публикует. Нельзя подменять их Linux-сборкой или выдавать Perl за полный native тест. Для распространения бинарников отдельный сервер не обязателен: подойдут GitHub Releases.

## Состояния и выводы

Разделять результат теста, полноту покрытия и предполагаемую причину. Минимальный контракт: run_id, code_ref, profile_id, test_id, backend, planned/tested_bytes, state, reason, exit_code, timestamps и evidence paths. Существующий TSV-контракт дополняется environment.tsv и capabilities.tsv; JSON/единая схема событий — следующая стадия, не объявляется реализованной.

PASS — выполненный объявленный этап; FAIL — несовпадение или ошибка проверяемого пути; INCONCLUSIVE — недостаточно условий/покрытия; OBSERVED — только сведения; NOT_RUN — не запускался; INTERRUPTED — прерван; BLOCKED — политикой запрещён. Недоступный Release, ограничение mlock, отсутствие Perl-модуля или компилятора не означают неисправный Mac. Нельзя автоматически снижать силу теста после уже обнаруженного mismatch и затем выдавать общий PASS.

Recovery-комплекс допускает наблюдения CPU/сети после неполного RAM screen, но помечает неустановленный RAM baseline и не выдаёт общую успешную приёмку. RAM mismatch останавливает дальнейшую нагрузку. RAW-перезапись остаётся заблокированной. Сведения/неполные проверки не скрывают FAIL.

## Журналы и обратная связь

Локально сохраняются bootstrap.log, probes.log (команда/rc/ошибка пробы), profile.txt, environment.tsv, capabilities.tsv, summary.tsv, REPORT_RU_EN.md и журналы движков. Профиль сохраняется ещё до меню, в том числе при выходе без тестов. Временные /tmp-журналы Recovery надо сохранить на внешний смонтированный том; имя RESCUE само по себе не доказывает, что том внешний. Автоматическое стирание/форматирование носителей журналов запрещено. Сохранность последних буферов при пропадании питания не гарантируется.

Пункт 19 создаёт локальный support-review.* и при наличии tar архив: только allowlist метаданных/состояний и ISSUE_DRAFT.md. Нет автоматической отправки, токенов, серийного номера, IP, путей пользователя или сырых журналов. Экспорт всё равно требует просмотра человеком. Правило allowlist снижает риск, но не является математической гарантией анонимности. Полные логи нужны для сложного случая: передавать отдельно по согласованному закрытому каналу, а не автоматически прикладывать к публичной заявке.

## GitHub или сервер

**Сейчас отдельный сервер не нужен.** GitHub — исходники, review, версии, Releases, обезличенные заявки. Полные логи — локально. Пользователь проверяет черновик и создаёт issue с исправного устройства. Никаких встроенных PAT, GitHub App private keys, общих upload-токенов в публичном shell. Не загружать автоматически дампы памяти, каталоги пользователя, переменные окружения и авторизационные данные.

Создание issue через REST требует авторизации; для fine-grained token документировано Issues(write). Технически direct submission возможно от имени пользователя, но хранить авторизацию на подозрительно нестабильном компьютере в Recovery не является хорошим стандартным потоком. Рекомендуемый первый выпуск — без такой функции.

**Сервер нужен при переходе к управляемому автоматическому приёму закрытых отчётов.** Отдельные компоненты: HTTPS intake API; одноразовое краткоживущее разрешение на upload; приватное объектное хранилище; метаданные заявки; лимиты размера/частоты; quarantine/проверка архива; удаление по сроку и запросу; контроль доступа и аудит чтений. В публичный GitHub уходит только очищенное описание с correlation ID. Нельзя считать, что приватный Git-репозиторий заменяет весь этот сервис и его политику доступа. Сервер не должен уметь посылать произвольные команды клиенту и не участвует в вынесении локального PASS.

Бинарники, manifests и обратная связь должны иметь разные разрешения и разные потоки данных. Ошибка endpoint обратной связи не влияет на возможность локальной диагностики и не превращается в аппаратный FAIL. Offline-сеанс сохраняет пакет для последующей отправки, но фоновую отправку без согласия не запускает.

## Жизненный цикл дефекта

1. Зафиксировать профиль, ревизию, backend, фактический объём и самый ранний сбой.
2. Отделить ошибку скрипта/зависимости/сети от наблюдаемого нарушения данных.
3. Воспроизвести на fixtures или контролируемом fault injection; не менять тестируемый Mac молча.
4. Добавить регрессию сначала на ошибочный сценарий, затем исправление и позитивный сценарий.
5. Проверить все существующие сценарии, реальные Bash 3.2/Recovery, Intel и ARM на доступных стендах.
6. Публиковать неизменяемый пакет, затем атомарно менять descriptor стабильного канала. Иметь предыдущий release для отката. Не смешивать файлы между версиями.
7. Указать границы в release notes. Молчаливый optimistic PASS и выдуманный процент готовности запрещены.

Отдельные негативные тесты: отсутствующий исполняемый файл и Perl-модуль, найденный но неработающий бинарник, отказ mlock, ошибка архитектуры, неизвестная среда, зависший probe, неполный пакет, повреждённый manifest, ENOSPC/read-only/symlink, смена носителя, обрыв/HTTP/Range, Ctrl+C и отключение питания. Последнее нужно проверять на стенде, а не утверждать по unit-тесту.

## Валидация rc3

Сценарии и код написаны для расширяемой матрицы, но реальной macOS/Recovery в этой среде не было. Локальная проверка: Linux, имитированные ответы системных команд, настоящий Perl на малых RAM/file данных, сохранность контрольного файла, контролируемая инъекция ошибок, проверки privacy-export и предыдущие регрессии. Native binary distribution, полноценные 8–48 ГиБ из Recovery, все модели и сервер не объявляются готовыми. Точный итог текущего прогона — в RC3_QA.md.
