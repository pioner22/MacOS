# MacDiag Core 0.1.0 — общее ядро профилей и адаптеров

Первая реализованная версия общего слоя для диагностики и VPN. В репозитории добавлены отдельные `macdiag_core/` и `macdiag-core.sh`. Действующие `st.sh`, `vpn.sh` и `diagnostics_v2` не изменены и пока не используют новое ядро. Это не полная база всех Mac и не замена VPN-установщика.

## Первый запуск: только паспорт среды

```bash
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/macdiag-core.sh | bash
```

Без sudo, паролей, Homebrew, Python и установки пакетов. Загрузчик скачивает семь файлов ядра и реестра с закреплённого коммита, проверяет SHA-256, запускает сбор профиля и удаляет временные программные файлы. Само скачивание использует сеть; после него сборщик не делает сетевых запросов и не отправляет результаты. Он не меняет службы, маршруты, DNS, разделы или файловые системы. Чтение сведений об окружении не равно аппаратному тесту.

Сохранить паспорт в новый файл на рабочем столе:

```bash
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/macdiag-core.sh | bash -s -- profile collect --output "$HOME/Desktop/macdiag-profile.json"
```

Каталог должен существовать. Существующий файл не перезаписывается; для следующего снимка укажите другое имя. Права файла — 0600. Серийные номера, аппаратные UUID, имена пользователей и полный environment не собираются. Модель/сборка ОС и комбинация аппаратных характеристик всё равно могут характеризовать устройство; не следует автоматически публиковать паспорт.

## Уже работает

| Компонент | Реализация |
|---|---|
| Паспорт | Модель, CPU, RAM, архитектура процесса, признаки Rosetta, загруженная ОС/build, среда с уровнем уверенности, фактический Bash запуска и системный Bash |
| Инструменты | Фиксированные системные пути, наличие/версии, доступные отпечатки файлов, отдельные безопасные пробы нужных возможностей |
| Реестр | 13 документальных записей для 11 идентификаторов MacBook Pro, 9 составных правил, 11 контрактов операций |
| Выбор | По наблюдениям; неоднозначность блокируется. Год устройства не определяет Bash; повторяющийся Model Identifier сохраняет несколько кандидатов года |
| Адаптеры | Инвентаризация, маршруты IPv4/IPv6, сводка DNS, чтение состояния службы, HTTPS и внешний IPv4 |
| Политика | Никакой сети по умолчанию; только известные операции; ручной профиль может ограничить, но не подменить факты |
| Отчёт | JSON, отпечаток совместимости, сравнение двух паспортов, отдельные PASS/FAIL/ERROR/SKIP/BLOCKED |

Библиотеки: `Detect.pm`, `Registry.pm`, `Adapters.pm`, `Runner.pm`. Диспетчер: `bin/macdiag.pl`, вход: Bash `macdiag`. Реестр: `registry/catalog.json`. Документация RU/EN раздельная: `macdiag_core/README_RU.md`, `macdiag_core/README_EN.md`.

Сборщик и библиотеки используют только существующий системный Perl с проверяемыми стандартными модулями. При отсутствии движка/необходимых возможностей выдаётся ограниченный отчёт UNKNOWN, а не попытка установить зависимости или продолжить без защит. Наличие модулей во всех Recovery не предполагается.

## Ключи запуска

Показать подходящие проверки:

```bash
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/macdiag-core.sh | bash -s -- tests list --compatible
```

Построить план будущей установки VPN без её выполнения:

```bash
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/macdiag-core.sh | bash -s -- plan --workflow vpn.install
```

Разрешить отдельную проверку внешнего IPv4:

```bash
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/macdiag-core.sh | bash -s -- run --test network.ip --policy diagnostic --allow-network
```

Она выполнит HTTPS-запрос к ifconfig.me. Сервис увидит IP, результат не доказывает VPN сам по себе. При неизвестной среде или неподтверждённых возможностях запрос будет заблокирован/пропущен, а не выполнен принудительно.

Для локальной копии: `bash macdiag_core/macdiag` с теми же аргументами. Сохранённый JSON допускается для плана и сравнения, но `run --snapshot ...` запрещён: исполняемые операции используют новый живой профиль. JSON содержит данные, а не команды для shell/eval.

## Что пока не реализовано

`vpn.install`, `network.speed`, `storage.readonly`, `memory.stress` присутствуют как контракты, но возвращают BLOCKED / NOT_IMPLEMENTED. Нет скрытого перехода к старому VPN. Подробная инвентаризация накопителей/GPU, полный каталог моделей и ревизий инструментов, автоматическая миграция существующих скриптов и полноценные изменяющие систему адаптеры — следующие отдельные этапы.

## Доказательства

На Linux (Bash 5.2.37, Perl 5.40.1, Python 3.13.5) прошли:

- 98 проверок библиотек Perl;
- 14 тестов реальной командной строки;
- 8 тестов загрузчика с локальной подменой скачивания.

Итого 120 проверок. Реальные fork/exec, ограничение времени/вывода, завершение потомка, права файлов и отказ от перезаписи испытаны. Системные действия Mac моделируются. Проверки загрузчика не являются измерением доступности GitHub из сети пользователя. Git blob SHA пятнадцати первоначально опубликованных файлов совпали с локальными; загрузчик закрепляет SHA-256 семи исполняемых компонентов/данных.

**Не испытано на настоящем Bash 3.2, штатном Perl Big Sur/Recovery, Apple Silicon/Rosetta и macOS launchd/DNS.** Ни одна запись реестра не помечена как REAL_HARDWARE_VALIDATED. Прохождение Linux-тестов не заменяет испытание на целевой системе. Первый шаг на Mac — сбор паспорта без сетевых разрешений.

Полный повтор тестов разработчиком: `bash macdiag_core/tests/run.sh`. Python нужен только разработческим тестам, не пользователю. Сводка — `docs/macdiag-core/VALIDATION.md`; журнал — в архиве `docs/macdiag-core/validation.log`.

Первая команда `curl | bash` доверяет HTTPS GitHub и содержимому загрузчика в main; хеши компонентов не являются отдельной подписью самого загрузчика. В автоматизации с анализом exit code включайте pipefail вызывающей оболочки: без него ошибка самого первого curl может не отразиться в коде всего конвейера.

Следующий этап — собрать паспорта реальных Big Sur full/Recovery, уточнить адаптеры по этим данным и только после проверки подключать новое ядро к существующим VPN и аппаратным тестам.
