# SSH-прокси для macOS Recovery — 1.0.2

`proxy.sh` создаёт фоновые SOCKS5 и HTTP/CONNECT-прокси через ваш SSH-сервер и временно задаёт системные настройки прокси текущей сессии Recovery.

**Это не VPN и не маршрутизация всего трафика.** Программы, игнорирующие прокси, UDP/QUIC и часть DNS могут обращаться напрямую. Скрипт не работает до загрузки Recovery, на экране глобуса и после перезагрузки Mac. Для этих этапов нужен туннель на отдельном шлюзе. Прокси не отменяет проверки T2 и не исправляет аварию установщика.

## Изменения 1.0.2

По запросу владельца встроены сервер `87.251.87.17` и SSH-пользователь `admin`. Вводить адрес и логин заново не нужно. Порт по умолчанию 22, но он по-прежнему запрашивается: фактический порт сервера не проверен. Пароль не встроен и не хранится.

В опубликованной версии 1.0.0 строка 452 вызывала `uname -s` для проверки платформы — это не запрос SSH-логина. Теперь используется доступный `sw_vers -productName`, а `uname` вызывается только при наличии и необходимости. Добавлены `--version` и явная ошибка при закрытом интерактивном вводе. Без точного текста ошибки пользователя её причина не считается доказанной: исправлена подтверждённая зависимость старой строки от наличия `uname`.

## Требования и запуск

На Mac нужны root (в Recovery уже есть), Bash 3.2, ssh, curl, scutil и стандартные утилиты. На сервере должны быть разрешены SSH-перенаправления и выполнение удалённых команд, а также установлен Python 3.6+. Отсутствующая зависимость останавливает запуск; автоматической установки пакетов нет. Root на сервере не обязателен.

```bash
curl -fL "https://raw.githubusercontent.com/pioner22/MacOS/rescue/proxy.sh?v=102" -o /tmp/proxy.sh
```

Только после успешного скачивания:

```bash
bash -n /tmp/proxy.sh && bash /tmp/proxy.sh start
```

Вы увидите `RECOVERY SSH WEB PROXY 1.0.2`, адрес и логин. Введите SSH-порт (Enter выбирает 22) и подтверждение 1. Пароль запрашивает **сам OpenSSH**, скрипт не сохраняет его и не передаёт через аргументы. Перед первым подтверждением проверьте fingerprint ключа сервера. Новое удалённое подключение в меню Terminal отдельно открывать не нужно.

SSH уходит в фон после аутентификации (`-fNT`). SOCKS слушает `127.0.0.1:1080`; HTTP/HTTPS — `127.0.0.1:18080`. Для HTTP временно выполняется Python-код на сервере, только на loopback и случайном порту, без создания постоянной службы, установки пакетов и изменения firewall. HTTPS передаётся через CONNECT без подмены сертификатов. Максимальная жизнь удалённого посредника — 24 часа; штатное закрытие SSH завершает его раньше.

Перед применением настроек проверяются HEAD-запросы к Apple через оба прокси. HTTP-статусы ошибок отмечаются предупреждением: получение ответа не равно разрешённому доступу. Даже успешный тест не подтверждает доступность каждого пакета macOS.

`PROXY_READY` означает запуск туннеля и подтверждение временных параметров через `scutil --proxy`, а не гарантированный охват всех компонентов установщика. Фоновые процессы позволяют вернуться к установщику в той же сессии Recovery. При замене среды/перезагрузке туннель прекращается. На конкретном Recovery такое переключение ещё не проверено.

## Управление

```bash
bash /tmp/proxy.sh --version
bash /tmp/proxy.sh status
bash /tmp/proxy.sh test
bash /tmp/proxy.sh stop
```

Если старая версия уже запущена, сначала штатно остановите её; не запускайте два экземпляра одновременно. При ошибке остановки не удаляйте каталог состояния вручную.

Копия управления: `/private/tmp/mac-ssh-proxy/run.sh`. Журналы находятся в `/private/tmp/mac-ssh-proxy`; права каталога 700. Там сохраняются адрес и логин сервера, host keys и прежние сетевые настройки, но не пароль. Не публикуйте весь каталог без проверки.

Изменяются только динамические словари SystemConfiguration, не постоянные сетевые файлы. Фоновый монитор пытается восстановить исходные параметры при остановке/обрыве SSH/смене сетевого сервиса, если изменённые словари всё ещё принадлежат этой сессии. Новая чужая конфигурация при возврате не перезаписывается. При неудачном возврате резервные словари сохраняются, выводится ошибка. Это **не kill switch**: после возврата прежних настроек прямые соединения могут возобновиться. Повторное подключение требует новой аутентификации пользователя.

## Проверки

Пройдено 33 теста на Linux: синтаксис Bash; проверка платформы при отсутствии uname; предустановленные реквизиты; отмена и закрытие ввода; валидация параметров; моделируемые операции scutil, возврат настроек, смена сети и разрыв SSH; реальные локальные HTTP GET/HEAD/POST/Range и CONNECT; остановка временного посредника. **Реальный SSH-сеанс с сервером пользователя и macOS Recovery интеграционно не тестировались.** Модель scutil не доказывает совместимость с конкретным Recovery или установщиком.
