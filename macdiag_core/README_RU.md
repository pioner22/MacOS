# MacDiag Core 0.1.0

Общий профиль устройства/окружения, справочник возможностей, адаптеры и диспетчер проверок. Это первый работающий слой инфраструктуры, **не завершённая база всех Mac и не новый VPN-установщик**. Действующие `st.sh`, `vpn.sh` и `diagnostics_v2` не изменяются и пока не используют это ядро.

## Запуск из локальной копии

Из корня репозитория, без sudo:

```bash
bash macdiag_core/macdiag profile collect
bash macdiag_core/macdiag profile collect --output profile.json
bash macdiag_core/macdiag tests list --compatible
bash macdiag_core/macdiag run --suite basic
bash macdiag_core/macdiag plan --workflow vpn.install
```

`--output` создаёт НОВЫЙ файл с правами 0600; существующий файл не перезаписывается. Относительные пути считаются от исходного рабочего каталога пользователя. Без `--output` постоянный отчёт не создаётся. JSON в stdout: `--format json`.

Сетевые запросы требуют двух явных разрешений:

```bash
bash macdiag_core/macdiag run --test network.ip --policy diagnostic --allow-network
bash macdiag_core/macdiag run --suite network --policy diagnostic --allow-network
```

`network.ip` обращается к HTTPS ifconfig.me; `network.internet` проверяет HTTPS-объект GitHub. Сервисы увидят внешний IP пользователя. Ни одного из этих запросов нет при обычном сборе профиля. Загрузка самой программы с GitHub — отдельный сетевой этап загрузчика, не операция сборщика. Автоматической отправки паспорта, телеметрии и VPN-ключей нет.

## Что уже реализовано

Сборщик фиксирует загруженную ОС и build, ядро, модель, CPU, RAM, архитектуру процесса, признак Rosetta при доступности, фактическую версию Bash запуска, версию системного Bash, наличие и версии инструментов. Для регулярных бинарников до 32 МиБ записывается SHA-256, когда чтение доступно. Серийные номера, UUID, имена пользователей, полный environment и содержимое дисков не собираются. GPU, подробные накопители и ОС на обслуживаемом диске явно помечены как не обследованные.

Режим среды выводится с уровнем уверенности: safe — по системному признаку; full/Recovery-like — по совокупности признаков, не по root UID. Локальное и интернет-восстановление не объявляются различёнными. x86_64 процесса не приравнивается к Intel. Неизвестный год не выводится из версии ОС или Bash.

Реестр содержит 13 документальных записей о 11 идентификаторах MacBook Pro, 9 правил выбора составного профиля и 11 контрактов модулей. Два идентификатора повторяются у разных поколений: возвращаются кандидаты, не выдуманный единственный год. Это стартовое наполнение по Apple, не перечень всех устройств. Ни одной записи REAL_HARDWARE_VALIDATED сейчас нет.

Работают 7 операций:

| ID | Действие |
|---|---|
| system.inventory | Факты профиля; не тест здоровья |
| tools.inventory | Инвентаризация утилит; не тест здоровья |
| network.routes | Read-only запросы маршрутов IPv4/IPv6, без изменения таблицы |
| network.dns | Чтение структуры DNS, количества резолверов; не аудит утечек |
| service.inventory | Read-only состояние службы launchd, по умолчанию ru.pioner22.bigsur-vpn |
| network.internet | Один HTTPS-запрос GitHub с проверкой TLS |
| network.ip | IPv4 через HTTPS ifconfig.me; смена IP сама по себе не доказывает VPN |

`network.speed`, `vpn.install`, `storage.readonly`, `memory.stress` описаны в реестре, но **BLOCKED / NOT_IMPLEMENTED**. План не запускает старый VPN скрытно. Никакого подключения, установки службы, монтирования, исправления диска, теста нагрузки или установки Python/Homebrew нет.

## Как устроено

`macdiag` — вход Bash 3.2+, сбрасывающий лишнее окружение и переходящий в доверенный каталог перед запуском движка. `bin/macdiag.pl` — диспетчер. `lib/MacDiag/{Detect,Registry,Adapters,Runner}.pm` — переиспользуемые библиотеки. `registry/catalog.json` — данные, не исполняемый код.

Движок использует существующий системный Perl и проверяемые стандартные модули JSON::PP, Digest::SHA, POSIX, IO::Select, Time::HiRes, Fcntl, Encode. Зависимости не скачиваются. При отсутствии Perl/необходимых возможностей оболочка выдаёт минимальный JSON с UNKNOWN и код 2, а не запускает диагностику без ограничений. Наличие этих модулей во всех Recovery НЕ предполагается.

Python нужен только для разработческих CLI-тестов. `/usr/bin/python3` на Mac инвентаризируется, но не запускается: это может быть установочный stub. Core Foundation, ctypes и новые бинарники здесь не используются.

Диспетчер применяет фиксированный allowlist операций и абсолютные пути системных программ. Строки реестра и профиля никогда не передаются в `eval`, shell или произвольный executable. `--profile auto|limited` позволяет только автоматический выбор либо дополнительное ограничение. Подменить модель/ОС/возможности ключом нельзя. Равноприоритетные правила дают AMBIGUOUS и блокируют операции.

Runner запускает только фиксированные команды адаптеров, с очищенным environment, отключённым stdin, монотонным временем, лимитом вывода и отдельной группой процессов. Сохраняемый лидер группы устраняет окно повторного использования PGID при очистке. Потомки, самостоятельно отделившиеся в другую сессию, не входят в гарантию; для недоверенных программ это не sandbox. Чтение/хеширование локальных файлов и общая длительность сборщика отдельно жёстким watchdog не ограничены; файловая система с зависшим I/O требует отдельной диагностики.

## Сохранённый профиль и изменения

```bash
bash macdiag_core/macdiag plan --workflow basic --snapshot profile.json
bash macdiag_core/macdiag profile diff --before old.json --after new.json
```

План из JSON помечается SAVED_SNAPSHOT_UNTRUSTED. `run --snapshot ...` запрещён: запуск ВСЕГДА заново собирает живые факты. Отпечаток включает build ОС, инструменты, их хеши, версию диспетчера, исходников ядра и реестра. Смена этих данных требует повторных проб. Сетевая ситуация меняется независимо от отпечатка, поэтому маршруты/DNS/службы проверяются заново при исполнении.

Состояния возможностей: MISSING, PRESENT_UNPROBED, UNKNOWN, UNSUPPORTED, VERIFIED. VERIFIED для curl.https_api означает успешную локальную пробу параметров и заявленную поддержку HTTPS, а не установленное соединение.

Состояния планов: AVAILABLE, SKIP, BLOCKED. AVAILABLE — разрешённая попытка, не PASS. Результаты адаптера маршрутов: FOUND, ABSENT, UNUSABLE, ERROR. Код 0 от Apple route не доказывает ни маршрут, ни его отсутствие: разбираются явные диагностические строки и флаги. ABSENT до подключения может быть нормой, а после подключения оценивается VPN-сценарием; ядро не смешивает эти контексты.

Коды CLI: 0 — запрошенные операции завершились/план построен; 1 — ошибка или FAIL; 2 — неполное выполнение, SKIP/BLOCKED либо отсутствие движка. PASS инвентаризации означает успешное чтение сведений, не заключение об исправности.

## Проверки и пределы доказательности

Локально на Linux выполнены 98 проверок Perl и 14 Python CLI-тестов. В них есть реальные fork/exec, тайм-ауты, ограничение вывода, завершение игнорирующего TERM потомка, JSON и права файлов. Mac-специфичные команды/окружения моделируются; сетевые запросы не выполнялись. Полный журнал и точные версии среды поставляются с архивом в `docs/macdiag-core/VALIDATION.md`.

**Не проверены:** настоящий Bash 3.2, системный Perl Big Sur, Recovery, Apple Silicon/Rosetta, реальные сетевые адаптеры Mac и настоящий launchd. Прохождение Linux-тестов этого не подтверждает. Первая проверка на Mac должна быть `profile collect`, без сетевых разрешений.

## Дальнейшая интеграция

1. Получить обезличенные паспорта реально запущенных Big Sur full/Recovery и других целевых систем. Не загружать их в публичный Git автоматически.
2. Дополнить fixtures вариантами реального вывода; отделить доказательства парсера от доказательств целевого оборудования.
3. Добавить режим сравнения нового плана с текущим diagnostics_v2, пока без передачи управления.
4. Перевести чтение curl/route/служб/DNS в VPN на адаптеры после Mac-проверки. Установка/остановка требуют отдельного контракта владения и отката.
5. Добавлять аппаратные модули отдельно, с пределами нагрузки и согласием на запись, а не превращать неизвестный профиль в максимальный стресс-тест.
