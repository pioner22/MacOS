# BigSurVPN 2.1.1 — выбор Xray или резервного SOCKS5

Дата: 21 сентября 2026 года. Целевая среда: установленная macOS Big Sur 11.x Intel. Это не версия для Recovery.

## Установка, обновление и выбор

После публикации этой версии в main используется одна постоянная команда:

```sh
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/vpn.sh | bash
```

Установщик запрашивает административные права и предлагает:

```text
Выберите подключение:
  1 — Xray (VLESS / Trojan)
  2 — SOCKS5 резервный
  0 — Отмена
```

Временные реквизиты резервного сервера, предоставленные владельцем, включены в отдельный файл данных `vpn-profile.json`. Повторно вводить их не требуется. Выбор читается из `/dev/tty`, а не из входного потока загружаемого shell-скрипта. Некорректный ввод, отсутствие терминала или отмена не переключают подключение.

При первой установке устанавливаются программа и ядро, создаются конфигурация и служба. При повторном запуске установщик обновляет отличающиеся файлы и заново создаёт подключение. При совпадении проверенных файлов ядро повторно не скачивается. Выбранный режим сохраняется в закрытом каталоге; `on` затем использует его. Для смены режима повторить постоянную команду и выбрать другой пункт.

## Управление

```sh
vpn-bigsur status    # выбранный режим, процесс и маршрут; не новый тест интернета
vpn-bigsur test      # проверка подключения
vpn-bigsur report    # последний сохранённый отчёт
vpn-bigsur off       # остановить собственную службу и проверить очистку
vpn-bigsur on        # включить сохранённый режим
vpn-bigsur --help
vpn-bigsur --version
```

Справка и версия не требуют sudo. Остальные команды запрашивают административные права. Формы с двумя дефисами, включая `--status`, сохранены. `vpn-bigsur update` обновляет только подписку Xray; для SOCKS5 сообщает, что фиксированные реквизиты обновляются через установщик, и не обращается к старому провайдеру.

## Реализация резерва

Оба режима работают через существующие sing-box и TUN/launchd. Пункт Xray означает прежние VLESS/Trojan-профили, а не установку отдельного бинарного Xray-клиента. SOCKS5 реализован штатным outbound `socks` того же ядра. Отдельный клиент AmneziaWG не устанавливается.

Это НЕ первоначальный черновой вариант с системной галочкой SOCKS в macOS. Системные proxy-настройки через networksetup не меняются. Небезопасный черновик `vpn-socks.sh` и дублирующий старый `vpn-xray.sh` удалены из итогового дерева ветки. Сохранены одна команда, один управляющий runtime, одна служба и общая очистка временного DNS/TUN.

SOCKS5-режим использует только выбранный резервный сервер и не обновляет подписку аварийного Xray-провайдера. Автоматического переключения обратно на Xray нет: выбор пользователя явный.

Резерв ограничен TCP. DNS перехватывается и передаётся как HTTPS через выбранный прокси; другие UDP/ICMP-запросы в TUN отклоняются. Нет скрытого обхода через direct-outbound. Это не обещание поддержки всех приложений, игр, QUIC, звонков или произвольного UDP.

Сам SOCKS5 не шифрует транспорт. При обычной username/password-аутентификации пароль передаётся без шифрования SOCKS5; HTTPS защищает содержимое HTTPS-соединения, но не внешнюю SOCKS5-аутентификацию. Резерв следует использовать как временное аварийное решение.

## Проверки на Mac при запуске

Установщик сохраняет закрепление компонентов и проверку SHA-256 внутри загрузчика: пользователь ничего вручную не вычисляет. При обновлении скачанные компоненты и обе примерные конфигурации проверяются установленным ядром до остановки прежней службы.

После подключения выполняются проверки конфигурации, процесса launchd, TUN, тестовых IPv4/IPv6-маршрутов, временного DNS, DNS-ответа, HTTPS с проверкой сертификата и выходного IPv4. Сам факт запуска процесса или открытый TCP-порт не считается успешным VPN. При неудачной проверке новая сессия останавливается, результат не выдаётся за READY.

У успешного SOCKS5-подключения итог `READY_WITH_WARNINGS` / `PASS_WITH_WARNINGS`, код 2: ограничения TCP и отсутствие шифрования SOCKS5 намеренно отражены как предупреждение, а не замаскированы полным PASS. Код 1 означает ошибку; код 2 также используется для ошибок аргументов, поэтому следует читать текст и поле overall отчёта, а не один код завершения.

При переключении старая собственная служба останавливается. В этом промежутке возможен прямой интернет. Kill switch и автозапуск после перезагрузки не добавлены. Если ошибка произошла после остановки, автоматическое восстановление прежнего работающего туннеля не гарантируется. Чужие VPN и небезопасные пути установщик не исправляет принудительно.

## Локальные доказательства

Повторный прогон 21 сентября 2026 года: **133 теста, 133 успешных, 0 пропусков**.

Среда: Linux x86_64, Python 3.13.5, Bash 5.2.37. Проверки прав используют реальные временные каталоги и непривилегированные дочерние процессы; сеть, launchd и сам sing-box в lifecycle-тестах подменены.

```sh
python3 -m unittest discover -s tests -p 'test_vpn_*.py' -v
bash -n vpn.sh
```

Состав целевого набора: 51 проверка прав и CLI, 17 проверок переустановки/переподключения/загрузчика, 65 проверок SOCKS5-профиля, меню, выбора, изоляции от старой подписки и отката новой сессии. Проверено отсутствие секретов в меню и сообщениях валидации. Все шесть опубликованных программных файлов и файлов тестов сверены с локальными тестируемыми байтами по Git blob; внутренние SHA-256 runtime и профиля совпали с загрузчиком. Файл профиля также проверен побайтово, без вывода реквизитов в журнал тестов.

**Это не полный аудит всего репозитория и не подтверждённый PASS GitHub Actions.** Не проверены настоящая macOS Big Sur, штатные Python 2.7/Bash 3.2, ACL macOS, запуск загруженного macOS-ядра, реальные TUN/launchd/DNS и поведение приложений. Проверка схем ядром предусмотрена на целевом Mac, но не выполнена в Linux-среде этого прогона.

Прямое TCP-подключение к предоставленному резервному адресу из вычислительной среды получило ConnectionRefusedError до SOCKS5-аутентификации. В этой же среде не разрешалось имя github.com. Это не доказывает аварию резервного сервера: ограничения среды/маршрута не исключены. Работоспособность резерва, пароль, HTTPS и выходной IP из этой среды не подтверждены; их проверяет установщик при запуске на Mac.

## Временный доступ

Публикация реквизитов сделана по явному запросу владельца для временного резерва. Публичный профиль предоставляет доступ любому, кто его прочитает. После аварии необходимо отозвать/сменить пароль на сервере. Простое удаление файла или ветки не стирает секрет из истории Git и чужих копий. Проверки локальных прав 0700/0600 не делают публичный исходный профиль секретным.
