# Одна кнопка: приложение, затем подписка

Интеграция от 15 октября 2026 года. База — PR №19, коммит
`afc8887b9e815bc724354df82d1905c095bf8409`.
Этот документ дополняет прежний README и заменяет описание отдельной кнопки
проверки обновления приложения. Готовый устанавливаемый выпуск пока не создан.

## Подключённые компоненты

Кнопка окна и пункт меню вызывают один `UpdateCenter.checkForUpdates`.
`UnifiedUpdateWorkflow` связан с настоящими делегатом Sparkle, пользовательским
интерфейсом Sparkle, хранилищем продолжения и адаптером обновления подписки.
Это больше не отдельная библиотека, не подключённая к кнопке.

Порядок: проверенная последняя версия → подписка. Если найдена более новая версия,
сначала подтверждение установки, запись продолжения, установка и перезапуск.
Новый процесс читает фактический номер своей сборки, заново проверяет ленту и лишь
затем обновляет подписку. Само скачивание, пустая лента, несовместимый выпуск,
отмена или сообщение «нет обновления» без положительного подтверждения последней
сборки не разрешают второй этап.

`GatedUpdateDriver` использует штатные окна Sparkle, но не передаёт ответ «install»
до успешной записи продолжения. Отказ на последнем приглашении переводится в
отмену, а не в отложенную скрытую установку при выходе. Подписи архива и ленты,
HTTPS, фиксированный канал и требования подтверждения не отключены.

## Подписка установленного VPN

В приложение включён фиксированный ресурс `refresh_legacy_subscription.py`.
`LegacySubscriptionService` вызывает его с системным подтверждением прав
администратора. Пароли администратора приложение не получает и не сохраняет.

Адаптер принимает только опубликованный runtime BigSurVPN 2.1.3 с закреплённым
SHA-256, проверяет root-владельцев, типы файлов и закрытые каталоги, затем использует
существующую блокировку `command.lock`. Для Xray вызывается только обновление
подписки через сохранённую активную сессию. Для SOCKS5 возвращается отдельное
`notApplicable`, без обращения к подписке основного провайдера или замены реквизитов.
Другой runtime отклоняется — его поддержку нужно добавлять явно.

Кнопка не запускает установщик VPN, не вызывает `on/off`, не меняет маршруты или DNS
и не переписывает бинарный runtime. GUI получает только небольшой проверяемый JSON
результат. Реквизиты подключения не включены в новые исходники, продолжение и вывод.
Неопределённый или ошибочный ответ не выдаётся за успешное обновление.

В существующей CLI 2.1.3 команда `vpn-bigsur update` остаётся командой подписки.
Этот PR не меняет её значение и не устанавливается через повтор старой curl-команды.

## Продолжение и защита от параллельных операций

Задание продолжения хранится атомарно в пользовательском Application Support,
каталог 0700 и файл 0600, максимум 8 КиБ. Чтение не следует ссылкам, отвергает
дополнительные жёсткие ссылки и неподходящие права. Используются операции относительно
открытого дескриптора каталога и fsync. Межпроцессная блокировка не допускает двух
одновременных обновлений. В задании нет паролей; оно не является доказательством
установленной версии. Запоздалые события отвергаются идентификатором операции.

## Проверки этого прохода

- 90 Swift-тестов: 37 конфигурации, 36 последовательности и 17 интеграционных
  проверок метаданных/хранилища/экранирования — успешно.
- 123 Python-теста подготовки выпуска, проверочного запуска и адаптера — успешно.
- 12 целевых мутаций последовательности: все обнаружены, без выживших,
  ошибок сборки и тайм-аутов. После прогона исходник восстановлен.
- Перенесены усиленные тесты из прежнего мутационного аудита и исправление пропуска
  финального контроля размера stderr в тесте запуска приложения.

Среда: Linux x86_64, Swift 6.2.1, Python 3.13.5. Файлы, блокировки и Swift-код
переносимых компонентов реально исполнялись. Сеть и вызовы Apple/Sparkle в Python
подменены. SwiftUI/AppKit/Sparkle-файлы прошли только синтаксический разбор, не
нативную компиляцию. Не проверены авторизация macOS, подписанное обновление N→N+1,
фактическое обновление VPN-подписки на устройстве и запуск на Big Sur.

```sh
python3 -m unittest discover -s vpn/app/tests -v
cd vpn/app && swift test -j 2
```

Development-сборка сохраняет отключённый канал обновлений. Для рабочего выпуска
нужны нативная сборка, испытание на Big Sur, ключи издателя и подписанная лента.
Привилегированное переключение VPN и сетевой адаптер автоматического перебора
серверов этой поставкой не реализованы.

## Причина отказа облачной сборки установлена

При чтении Annotations публичного запуска GitHub Actions №36202244263
обнаружено одинаковое сообщение для `native-build` и `metadata`:

> The job was not started because your account is locked due to a billing issue.

Это сообщение GitHub, а не предположение по пустым логам. Настройки оплаты не
изменялись. Пока блокировка не снята владельцем аккаунта, облачная сборка и
нативные проверки не запускаются. Успехом CI или готовым приложением это не называется.
