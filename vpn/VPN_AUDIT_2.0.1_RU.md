# BigSurVPN 2.0.1 — повторный аудит 20 сентября 2026

## Результат

Найдены и исправлены ошибки логики, обработки неудачных проверок и очистки нового подключения. Текущий `vpn.sh` закреплён на исправленном runtime 2.0.1. Это не заключение об отсутствии любых ошибок и не подтверждение работоспособности на настоящем Big Sur.

Команда остаётся прежней:

```bash
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/vpn.sh | bash
```

VPN-ключ вводить не нужно; возможен запрос пароля администратора Mac. Исправленная версия показывает `BigSurVPN 2.0.1`. Схема профиля и опубликованная ссылка подписки не менялись.

## Исправленные проблемы

| Код | Проблема версии 2.0.0 | Изменение 2.0.1 |
|---|---|---|
| A01 | Любая ошибка `launchctl print`, включая тайм-аут, превращалась в «службы нет». Похожая проблема была в `ifconfig` и `route`. | Отсутствие, наличие и невозможность проверки различаются. Неизвестный результат не считается успешным отключением. |
| A02 | После подключения обновление подписки находилось вне области отката. Прерывание или ошибка записи могли оставить новый VPN включённым после неуспешного сценария. | Обновление включено в защищённую область. При обычной недоступности подписки работающий VPN сохраняется с WARN; при отмене/ошибке локального состояния нового подключения вызывается остановка. |
| A03 | Отдельная команда `on` не останавливала только что созданное подключение при провале второй проверки. | Введена явная граница владения новой сессией: сбой нового подключения вызывает откат, диагностическая проверка существующей сессии не отключает её автоматически. |
| A04 | Проверялось наличие системного DNS-резолвера, но контроллер не регистрировал его явно. Нельзя переносить предположения о графическом Apple-клиенте на CLI/TUN. | Добавлен процесс-супервизор launchd: он держит временную сессию SystemConfiguration и собственные ключи IPv4/IPv6/DNS. Постоянные настройки networksetup не перезаписываются. Реальная интеграция требует проверки на Mac. |
| A05 | DNS-тест доверял заголовку и заявленному числу ответов. Пакет без фактической записи A мог пройти. Поиск DNS-адреса и имени интерфейса был по подстроке. | Проверяется реальная структура DNS, ID, вопрос, тип/класс, усечение, границы записей, CNAME и достижимая запись A. Адрес резолвера и интерфейс сопоставляются точно. |
| A06 | Ограничение времени запуска процесса не покрывало блокирующую запись большого stdin в pipe. | Вход подаётся через закрытый временный файловый дескриптор; ожидание дочернего процесса ограничено тайм-аутом. Проверено реальным локальным процессом с большим stdin. |
| A07 | Отказ или ограничение GitHub API могло ошибочно блокировать установку при доступном GitHub raw. | Добавлен независимый HTTPS-запрос к закреплённому контрольному файлу raw с проверкой SHA-256. Контрольный файл не исполняется. |
| A08 | Две строки скорости загрузки могли считаться полным тестом Apple; не все ошибочные метрики обрабатывались корректно. | Загрузка и отдача проверяются отдельно, единицы нормализуются, нечисловые/отрицательные/бесконечные значения отклоняются. У curl дополнительно проверяется маршрут к фактическому CDN-адресу. |
| A09 | В Python 3 percent-decoding мог молча заменять неправильный UTF-8 в учётных данных. | Разбор байтов строгий; повреждённые URI отвергаются, пароль не меняется молча. |
| A10 | Успешный отдельный `test` не обновлял время последней проверки в active.json; отдельные неверные CLI-аргументы принимались неоднозначно. | Записываются новый IP и время проверки. Число аргументов команд проверяется явно. |

Остановка проверяет не только отсутствие службы и TUN-маршрутов, но и исчезновение собственных временных ключей и резолверов DNS. Сбой проверки/очистки выводится отдельно; гарантированное восстановление сети при любой аварии не заявляется.

Супервизор не создаёт отдельную сессию для дочернего ядра: его группа процессов остаётся под управлением launchd. При завершении ядра супервизор закрывает временную DNS-сессию. При обычной остановке также завершает и ожидает дочерний процесс. Исключение при закрытии DNS не пропускает попытку завершить ядро.

По документации Apple, SCDynamicStoreAddTemporaryValue не заменяет существующий ключ, а временное значение удаляется при закрытии сессии, если другая сессия не успела его изменить. Это свойство API, не доказательство уже выполненного испытания реализации на Big Sur.

## Воспроизведение на старой и новой версиях

В Linux/Python 3 с подменой границ ОС/сети отдельно выполнены четыре одинаковых сценария против точных исходников 2.0.0 и опубликованных байтов 2.0.1:

| Сценарий | 2.0.0 | 2.0.1 |
|---|---|---|
| Тайм-аут launchctl трактуется как отсутствие службы | Ошибка воспроизведена | Результат отклонён как неизвестный |
| Повреждённый UTF-8 в пароле принимается после замены | Ошибка воспроизведена | URI отклонён |
| DNS-пакет с ANCOUNT=1, но без записей ответа принимается | Ошибка воспроизведена | Пакет отклонён |
| Две строки Downlink без Uplink считаются полным тестом | Ошибка воспроизведена | Вывод WARN, полного PASS нет |

Эти сценарии не устанавливают соединение с VPN-провайдером.

## Что остаётся непроверенным и ограниченным

**Не подтверждены:** исполнение на штатном Python 2.7 Big Sur; вызовы CoreFoundation/SystemConfiguration на реальном Mac; публикация/удаление настоящего TUN DNS; загрузка и `check` legacy-ядра в среде разработки; реальное соединение с провайдером; реальные скорости; сон/пробуждение и смена Wi-Fi; трафик каждого приложения и полный аудит утечек.

Штатная networkQuality отсутствует в обычной macOS Big Sur. Она проверяется по наличию; при отсутствии выполняется резервная загрузка системным curl через TUN. Это один поток загрузки, не тест отдачи/RPM. SKIP/WARN остаются видимыми и дают `READY_WITH_WARNINGS`, код 2, а не безусловный READY.

Проверка IPv6-маршрутов не равнозначна испытанию фактической IPv6-передачи. Смена IP сама по себе не доказывает отсутствие утечек. Нет kill switch и автозапуска после перезагрузки. При выключении/аварии или обновлении версии возможен прямой интернет. Предыдущие файлы сохраняются, но автоматическое восстановление старой версии и прежнего соединения целиком не реализовано.

Внешняя короткая команда `curl | bash` без pipefail может вернуть статус последнего процесса bash при отказе самого первого скачивания. Сообщение ГОТОВО в таком случае не появляется, потому что сценарий не стартует. Для использования кода завершения всей цепочки в автоматизации следует включать pipefail в вызывающей оболочке. SHA-256 последующих компонентов не является отдельной подписью первого загрузчика из ветки main.

**Профиль остаётся публичным по предыдущему решению владельца.** Исправление программы не скрывает уже опубликованные VPN-данные, в том числе историю Git. Для закрытия ранее опубликованного доступа требуется перевыпуск учётных данных у провайдера. SIP, Gatekeeper, проверка TLS и firewall не отключаются.
