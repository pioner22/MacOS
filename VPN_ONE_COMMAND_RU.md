# BigSurVPN 1.1.0 — установка и подключение одной командой

`vpn.sh` теперь запускает цепочку **установка → настройка → подключение → проверка связи**. Отдельная команда `vpn-bigsur on` после успешной установки не нужна.

## Первый запуск

Персональная команда из чата имеет форму:

```sh
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/vpn.sh | VPN_INSTALL_KEY='<ключ уже подставлен в команде из чата>' bash
```

Это шаблон документации, а не готовая команда: используйте персональную строку из чата. В ней значение уже заполнено, отдельного приглашения для ключа нет. Пароль администратора macOS может быть запрошен через sudo; это не ключ VPN. Скрипт не отключает защиту macOS и не добавляет беспарольные правила sudo.

Ключ не опубликован в репозитории. Перед загрузкой других компонентов он удаляется из экспортируемой переменной окружения и затем передаётся установщику через stdin. В аргументы sudo/контроллера ключ не помещается. Сама персональная строка содержит секрет и может остаться в истории shell; не публикуйте её или снимки экрана с ней.

На машине с уже установленным профилем допустим повторный запуск без ключа:

```sh
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/vpn.sh | bash
```

На чистой машине эта сокращённая строка не расшифрует профиль: нужна персональная строка. Скрытого публичного ключа или автоматического получения секрета с другого сервиса нет.

## Поведение

Установщик скачивает закреплённые компоненты с GitHub, проверяет SHA-256, сохраняет профиль локально, запускает контроллер `on` и затем `test`. Существующая полная установка использует сохранённый профиль без переустановки. Изменённый контроллер с несовпадающей контрольной суммой автоматически не запускается.

Сообщение `ГОТОВО: VPN настроен, подключён; проверка HTTPS успешна.` появляется только после успешных команд подключения и проверки. При неудаче подключения/контрольного запроса вызывается `off` для собственной службы, возвращается ненулевой код завершения и выводится ошибка. Если сама остановка завершилась ошибкой, она также выводится; это не обещание гарантированного восстановления всех маршрутов в любой аварии.

Последующее ручное управление:

```sh
vpn-bigsur off
vpn-bigsur on
vpn-bigsur status
vpn-bigsur test
```

Сценарий рассчитан на установленную macOS Big Sur 11.x на Intel. Требуется штатный Python 2.7. Recovery и Apple Silicon этим установщиком не поддерживаются. Автозапуска после перезагрузки и kill switch нет.

Сетевой контроллер не изменялся: для первого соединения он использует два ранее предоставленных владельцем резервных профиля, затем обновляет встроенную подписку через VPN. Текущая работоспособность резервных профилей не подтверждена; при их отзыве первое соединение не гарантируется. Если обновление подписки не удалось, контроллер сообщает об этом и сохраняет работающее соединение.

## Проверки

20 сентября 2026 года в Linux выполнены **16 автономных тестов** `test_vpn_setup.py`: синтаксис Bash, контрольная сумма установщика, передача ключа без приглашения, отказ при отсутствующем/неверном ключе, последовательность install/on/test, повторное использование локального профиля и вызов off при моделируемых ошибках. Все 16 прошли. Тесты сетевых действий используют подмены функций, а не настоящий VPN.

Отдельно локально проверены HMAC и расшифровка встроенного профиля: ссылка подписки совпадает с предоставленной владельцем. Секреты не выводились в результат проверки и не добавлялись в публичные файлы.

**Не проверены здесь:** выполнение на Python 2.7/Big Sur, реальный запуск legacy-ядра, работа macOS launchd/TUN/DNS и соединение с серверами владельца. Локальные тесты не подтверждают эти пункты.
