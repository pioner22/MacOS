# BigSurVPN 2.0.0 — установка, профиль, служба и проверки

Актуальная инструкция для установленной **macOS Big Sur 11.x на Intel**. Не для Internet Recovery, Apple Silicon или macOS 12+. Старые `vpn-bigsur.py`, `vpn-bigsur.sh` и `VPN_BIG_SUR_RU.md` в репозитории относятся к предыдущей версии; текущая точка входа — `vpn.sh` и новый `vpn-runtime.py`.

## Одна команда

```bash
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/vpn.sh | bash
```

Без `VPN_INSTALL_KEY`, отдельного ключа расшифровки, ввода ссылки, ручного создания конфигурации и дополнительного `on` после установки. Возможен только запрос **пароля администратора Mac** через sudo. Скрипт не добавляет беспарольные правила sudo и не отключает защиту macOS.

При запуске должна появиться строка `BigSurVPN 2.0.0`. Скрипт скачивает отдельные `vpn-runtime.py` и `vpn-profile.json` с закреплённых коммитов GitHub, проверяет SHA-256 и повторяет проверку прочитанных байтов после получения прав администратора. Выполняется проверенная копия из временного каталога root.

**Предупреждение о доступе:** по явному требованию владельца персональная ссылка и резервные VPN-данные находятся в публичном `vpn-profile.json`. Любой скачавший его может использовать эти данные. Это не секретное хранилище; права 0600 локальной копии не скрывают публичную копию. После использования следует перевыпустить ключи/подписку у провайдера. Удаление файла из текущей ветки само по себе не удаляет его из истории Git.

## Порядок выполнения

| Этап | Проверка и действие |
|---|---|
| Среда | Big Sur, Intel, установленная система, штатный Python 2.7, права администратора |
| Интернет до VPN | HTTPS GitHub с проверкой сертификата; исходный IPv4 через `curl https://ifconfig.me/ip` |
| Установка | Загрузка legacy-ядра только с GitHub Release, SHA-256, безопасное извлечение, запуск `version` на Mac |
| Конфигурация | Проверка схемы профиля, генерация JSON, проверка настоящим `sing-box check`, сохранение профиля локально |
| Предварительное соединение | Попытка загрузить подписку, выбор совместимого сервера, HTTPS-проба через временный локальный прокси до изменения системных маршрутов |
| Служба | Создание приватного plist и `launchctl bootstrap` собственной службы |
| Туннель и интернет | Работающий процесс, интерфейс UP, маршруты IPv4/IPv6, DNS-резолвер macOS на TUN, реальный UDP DNS-ответ и HTTPS-запросы через системный маршрут |
| Адрес после VPN | IPv4 через HTTPS ifconfig.me, проверка маршрута к фактическому адресу сервиса, сравнение с исходным адресом |
| Скорость | Штатная `networkQuality`, если есть; иначе резервный замер системным curl без стороннего Speedtest |
| Итог | Повторная проверка после замера скорости, отчёт с результатами каждого этапа, вывод IP и состояния |

Проверка исходного IP и проверка после подключения используют одинаковое семейство адресов: curl запускается с `-4`. Это исключает ошибочное сравнение исходного IPv4 с последующим IPv6.

Процесс службы или изменение IP по отдельности не считаются достаточной проверкой. Дополнительно проверяются маршруты к обеим половинам адресного пространства IPv4/IPv6 и к фактическим адресам HTTPS-сервисов, системный DNS и реальный доступ в интернет. Проверка маршрута IPv6 не равнозначна проверке реальной передачи IPv6-данных.

Если GitHub недоступен на исходной проверке, установка не продолжается. Если доступен GitHub, но исходный ifconfig.me недоступен, скрипт всё же пробует VPN; сравнение адресов получает WARN, а не выдуманный PASS. Если исходный IP известен и после подключения он не изменился, критерий готовности не пройден: новое подключение останавливается. Это диагностический критерий сценария, а не самостоятельное доказательство обхода туннеля.

## Профиль и подписка

`vpn-profile.json` содержит новую ссылку подписки и два ранее предоставленных владельцем резервных URI. Их текущая работоспособность в среде подготовки не подтверждена. Сначала скрипт пытается получить актуальную подписку, затем пробует совместимые сохранённые/резервные серверы. После подключения подписка обновляется через VPN. Неудача обновления не разрывает исправное соединение, но отмечается предупреждением.

Принимаются URI-список или Base64 такого списка: VLESS/Trojan TLS, VLESS REALITY TCP, TLS WebSocket/gRPC в поддерживаемых режимах. Неизвестные параметры, отключение проверки TLS, произвольный конфигурационный JSON, VMess и xhttp этой версией не импортируются. Xray spiderX не переносится; соединение проверяется отдельно. Данные подписки не исполняются как код.

Устанавливается **профиль sing-box с системным TUN**, не встроенный профиль IKEv2/L2TP и не mobileconfig. Запись в штатной панели VPN macOS не создаётся. Служба называется `ru.pioner22.bigsur-vpn`, интерфейс — `utun98`. Из окна Терминала управляется служба launchd, а не фоновый процесс, привязанный к открытой вкладке.

## Скорость без стороннего Speedtest

Apple `networkQuality` доступна начиная с macOS 12; в обычной Big Sur её нет. Скрипт проверяет реальное наличие `/usr/bin/networkQuality`, а не пытается скачать её или установить несовместимый пакет.

При наличии утилиты запускается `networkQuality -I utun98 -v` с общим ограничением времени 120 секунд. Показываются значения самой утилиты; проверяются её успешное завершение и положительные значения пропускной способности загрузки/отдачи.

При отсутствии утилиты выводится SKIP для теста Apple и выполняется резервный замер **штатным curl**: один HTTPS-поток скачивает с GitHub CDN объект размером 26 335 501 байт в `/dev/null`, с привязкой к utun98 и ограничением 90 секунд. Дополнительный тестовый файл на диск не сохраняется. Результат — скорость загрузки в Мбит/с. Это не измерение отдачи, задержки под нагрузкой, максимальной полосы канала или полноценная замена networkQuality. Неполное скачивание не выдаётся за успешный замер.

## Результат и ошибки

`READY`, код 0 — все предусмотренные проверки пройдены без WARN/SKIP:

```text
ГОТОВО: VPN успешно установлен, настроен, подключён и готов к работе. Все предусмотренные проверки пройдены.
```

`READY_WITH_WARNINGS`, код 2 — туннель и интернет проверены, но есть ограничения, например отсутствие networkQuality, неизвестный исходный IP, неудачное обновление подписки или неудачный замер скорости. Работающий VPN остаётся включённым. Для обычной Big Sur это ожидаемый вариант при отсутствии networkQuality, даже если резервный замер загрузки успешен. Сообщение прямо указывает на предупреждения; это не полный PASS всех тестов.

`FAILED`, код 1 — критическая ошибка. При провале запуска или проверки нового подключения скрипт пытается остановить только собственную службу и проверяет исчезновение TUN/маршрутов. Неуспешный откат также показывается как ошибка. Это не обещание полного восстановления сети при любой аварии. Отдельная диагностическая команда `test` не отключает существующую сессию автоматически.

Ошибки curl различаются по коду: DNS, TCP, HTTP, тайм-аут, TLS-рукопожатие, сертификат и размер ответа. Сообщение о готовности не выводится при критической ошибке. Последний отчёт сохраняется локально без исходных URI/паролей; он содержит IP и имя профиля, поэтому тоже не является полностью обезличенным.

## Повторный запуск

При той же проверенной установленной версии и уже работающей сессии скрипт не переустанавливает программу и не отключает VPN: повторно проверяет соединение. Для сравнения используется сохранённый исходный IP с временем его получения, а не текущий VPN-адрес, ошибочно названный исходным.

При смене версии сначала скачиваются и проверяются новые файлы, пока прежняя служба ещё работает. Затем собственная служба останавливается для нового исходного замера и подключения. На этом этапе обычный прямой интернет временно возможен. Предыдущий каталог версии и резервные копии конфигурации сохраняются; автоматическое восстановление предыдущей версии/сессии целиком не реализовано.

## Управление

```bash
vpn-bigsur on          # Включить с проверками соединения
vpn-bigsur off         # Выключить и проверить остановку
vpn-bigsur status      # Состояние процесса и данные последнего теста
vpn-bigsur test        # Новые проверки DNS, маршрутов, HTTPS и IP
vpn-bigsur speed       # Проверка VPN, замер скорости, повторная проверка
vpn-bigsur report      # Полный последний отчёт по этапам
vpn-bigsur logs        # Ограниченный журнал запуска/проверки JSON
vpn-bigsur list        # Профили
vpn-bigsur select 2    # Приоритетный сервер для следующего включения
vpn-bigsur update      # Обновить подписку через работающий VPN
vpn-bigsur uninstall   # Остановить и удалить программу/локальные данные
```

Если PATH не содержит `/usr/local/bin`, используйте `/usr/local/bin/vpn-bigsur` с той же командой.

Файлы установки находятся в `/Library/BigSurVPN`. Закрытые данные: `private/provider-profile.json`, `private/profiles.json`, `private/config.json`, `private/runtime.plist`, `private/active.json`, `private/last-report.json`. Каталог private — root 0700, создаваемые файлы — 0600. Версии ядра/контроллера — в `releases`, активная версия — ссылка `current`.

**Автозапуска после перезагрузки нет. Kill switch нет: при выключении или аварии ядра возможен прямой интернет.** После перезагрузки используйте `vpn-bigsur on`. Сценарий не является полным аудитом DNS-утечек, UDP, всех приложений, сна/пробуждения и переключений Wi-Fi. SIP, Gatekeeper, TLS-проверка и системный firewall не отключаются. Журнал каждого соединения отключён; служебные логи ограничены размером.

## Проверки разработки

20 сентября 2026 года на Linux с Python 3 повторно выполнены **68 автономных тестов** `test_vpn_runtime.py`: все 68 прошли. Проверены синтаксис Bash, URI/Base64, JSON, права файлов, безопасное извлечение, контрольные суммы, ограничение времени процесса, HTTP-параметры и реальные stdin/stdout локальных процессов. Сетевые проверки macOS, служба, маршруты, DNS, условия успеха/ошибки, откат, повторный запуск и замеры скорости проверены с подменами функций, не настоящей сетью Mac.

Отдельно испытан встроенный загрузчик с безвредным тестовым runtime: корректные проверенные байты запускаются с профилем, неверный SHA-256 блокирует запуск. Проверено, что команда не требует VPN_INSTALL_KEY, а неполный скрипт без заключительного вызова не исполняет установку. Git blob SHA опубликованных скрипта, runtime, профиля и тестов совпали с локальными файлами.

**НЕ ПРОВЕРЕНО в среде разработки:** исполнение на Python 2.7 Big Sur, запуск legacy-ядра на Mac, реальная проверка JSON ядром, фактическое соединение с провайдером, системный TUN/DNS на Mac и реальные значения скорости. Эти проверки выполняет сценарий на целевом Mac. Локальные 68 PASS не подтверждают их заранее.

Разработчику для автономного повторения тестов (Python 3, Linux):

```bash
python3 test_vpn_runtime.py
bash -n vpn.sh
```
