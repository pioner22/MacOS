# Загрузка Catalina на втором Mac — 1.0.0

`download-catalina.sh` предназначен для обычной macOS на исправном втором Mac (в данном случае A1398 / Big Sur), а не для Recovery A2141. Скрипт получает **один** файл `InstallESDDmg.pkg` продукта `001-68446`, сохраняя его оригинальное содержимое. Он не создаёт локальный сервер или USB-установщик и не устанавливает macOS.

## Запуск

В Терминале A1398, **без sudo**:

```bash
/usr/bin/curl -q -fL --proto '=https' --proto-redir '=https' https://raw.githubusercontent.com/pioner22/MacOS/rescue/download-catalina.sh -o "$HOME/download-catalina.sh" && /bin/bash -n "$HOME/download-catalina.sh" && /bin/bash "$HOME/download-catalina.sh"
```

Окно Терминала оставить открытым, питание подключить, крышку не закрывать. `caffeinate` предотвращает автоматический сон, пока работает скрипт. Это не защита от отключения питания или зависания. Постоянная служба не создаётся.

Файлы сохраняются в:

```text
~/macOS-rescue/Catalina-001-68446/
    InstallESDDmg.pkg.part       # частичная загрузка
    InstallESDDmg.pkg            # передача завершена и размер совпал
    InstallESDDmg.sha256         # собственный отпечаток сохранённых байтов
    source.meta                 # URL, размер и ETag/Last-Modified
    transfer.ok                 # запись об успешном завершении curl
    logs/<UTC>-<PID>/
        summary.txt
        head-*.txt
        get-*.headers
        get-*.curl.log
        verification.txt
        curl-version.txt
```

При ошибке подписи или проверки образа уже полученный файл **не удаляется**, но результат `READY_FOR_REVIEW` не выводится. Сам факт наличия файла с расширением `.pkg` не означает, что все проверки прошли.

## Поведение загрузчика

Предустановлен HTTPS-вариант точного пути из журнала пользователя. Исходный установщик обращался по HTTP: успех данного скрипта **не доказывает успешность оригинального HTTP-запроса**. Никакого незаметного перехода на HTTP, `--insecure`, смены даты или доверия сертификатам нет.

Используется системный `/usr/bin/curl`, IPv4, HTTP/1.1, без HTTP/SOCKS-прокси для данного запроса. Это не выключает системный VPN/TUN и не меняет маршруты или настройки других приложений.

Сначала выполняется HEAD к файлу. Требуются итоговый HTTP 200, корректный Content-Length (до 40 ГиБ) и не текстовый Content-Type. При отказе HEAD или неизвестном размере скрипт останавливается: GET тогда не проверен. На диске должен оставаться запас 2 ГиБ сверх ещё не полученных данных.

Показывается стандартный прогресс curl: проценты, байты, скорость, время. При возобновлении проценты/ETA относятся к оставшейся передаче; полный ожидаемый размер и смещение выводятся отдельно. Заголовки, коды curl, IP назначения, фактический размер файла и время запроса записываются в журнал.

В одном запуске — не более трёх GET-попыток. Автоматически повторяются только определённые ошибки соединения/передачи, с паузой 10 секунд. Один GET ограничен двумя часами, 120 секунд со скоростью менее 1 КиБ/с приводят к остановке текущего запроса. Сертификатные ошибки, неверный HTTP-ответ, локальная ошибка записи или аварийный код процесса не маскируются бесконечными повторами.

Для повторного запуска:

```bash
/bin/bash "$HOME/download-catalina.sh"
```

Дозагрузка допускается, только когда совпали URL, размер, ETag или Last-Modified и сервер поддерживает Range. Посылается If-Range; проверяются итоговый Content-Range и заголовки. При отсутствии валидатора или изменении метаданных файл сохраняется, автоматическое продолжение блокируется. Частичные файлы из прежних ручных запусков без метаданных **не импортируются**.

При подозрительном ответе появляется `unsafe-partial`; для исследования сохраняются журналы и данные. Не удаляйте этот маркер ради обхода проверки. Для новой независимой попытки предусмотрен другой каталог:

```bash
/bin/bash "$HOME/download-catalina.sh" --output "$HOME/macOS-rescue/Catalina-new-attempt"
```

Одновременный запуск в один каталог запрещён lock-файлом. При обычной остановке Ctrl+C частичный файл сохраняется и блокировка снимается. Для `source.meta`, журналов и данных используется отдельный каталог с правами 700.

## Проверки после передачи

`DOWNLOAD_OK` означает успешный curl и совпавшее число байтов. Затем вычисляется SHA-256. Без доверенного эталонного хеша это только отпечаток, не самостоятельное доказательство подлинности.

Проверяется реальный формат, а не только расширение:

* XAR/PKG: `pkgutil --check-signature`; сохраняются код возврата и информация о подписанте. Сам пакет не запускается.
* UDIF/DMG (некоторые файлы `InstallESDDmg.pkg` являются образами): `hdiutil verify`. Файл не переименовывается и не монтируется. Внутренние подписи пакетов/отзыв сертификатов этой проверкой не подтверждаются.
* Неизвестный формат: остановка, без использования файла в установке.

`READY_FOR_REVIEW` — передача и соответствующая команда проверки прошли; это не гарантия установки или доказательство исправности каждого компонента компьютера. Журнал подписи/образа нужно просмотреть перед локальной выдачей файла A2141.

## Ограничения и фактическое тестирование

Проверены 29 локальных регрессионных тестов на Linux: настоящие запросы curl к локальному HTTP-серверу, обрыв и дозагрузка, Range, смена ETag, отсутствие метаданных/места, ограничения повторов, SHA-256, блокировки и разделение PKG/DMG. `pkgutil` и `hdiutil` в тестах заменены заглушками; файловая статистика адаптирована к GNU stat. Основная обвязка macOS и `caffeinate` на Big Sur здесь не запускались. Bash-проверка выполнена установленным в среде Bash, не штатным Bash 3.2 macOS. Полная загрузка реального пакета Apple не проводилась: DNS вычислительной среды не разрешает swcdn.apple.com. Это ограничение среды проверки, а не отказ Apple.

Никаких обновлений Homebrew/Python, демонов, SSH, DNS, VPN, форматирования, подключения DMG или запуска установщика скрипт не выполняет.
