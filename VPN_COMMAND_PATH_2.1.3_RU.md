# BigSurVPN 2.1.3 — установка независимо от /usr/local/bin

Дата: 21 сентября 2026 года. Исправление повторного отказа до меню выбора VPN.

## Причина

На последнем снимке пользователя уже загружен установщик 2.1.2 и оба файла проходят проверку SHA-256. Ошибка теперь относится к типу или режиму `/usr/local/bin`, а не обязательно к владельцу. По снимку нельзя определить фактический режим каталога. Отказ прежнего кода воспроизведён в изолированной Linux-среде на каталоге с правами 0775.

Предыдущий фикс разрешал безопасного пользовательского владельца, но сохранял обязательный запрет group/world-write и символических ссылок. Общий каталог команд не должен быть обязательной зависимостью установки собственного защищённого VPN.

## Исправление

Авторитетная команда теперь находится в собственном каталоге:

```text
/Library/BigSurVPN/vpn-bigsur
```

Это принадлежащая root ссылка на `/Library/BigSurVPN/vpn-bigsur.sh`. Оболочка имеет права 0755 и повышает привилегии только через фиксированный защищённый путь. Каталог `private` остаётся 0700, приватные файлы — 0600. Проверки собственных файлов, типов, владельцев и дополнительных жёстких ссылок не ослаблены.

`check_activation_paths` больше не вызывает проверку общего каталога `prepare_command_dir`. Последняя функция сохранена для совместимости, но не участвует в пути установки. Существующие `/usr/local` и `/usr/local/bin` не получают chown/chmod; ссылки в этих путях не обходятся и их содержимое не переписывается.

При безопасных root-owned общих каталогах возможно создание прежней ссылки `/usr/local/bin/vpn-bigsur` для удобства. Если каталог отсутствует, имеет неподходящие права, владельца или тип, эта необязательная операция пропускается, а установка продолжается через собственную команду. Диагностика сообщает uid/gid/mode проблемного общего пути. Чужая команда не заменяется.

Короткое имя регистрируется через отдельный файл `/private/etc/paths.d/ru.pioner22.bigsur-vpn`, содержащий `/Library/BigSurVPN` и перевод строки. Предварительно проверяются реальные root-owned предки. Файл имеет права 0644; пользовательские `.zshrc`, `.zprofile` и `.bash_profile` не редактируются. Ошибка регистрации PATH даёт предупреждение и не удаляет рабочую команду по полному пути. При удалении проверяются точное содержимое и принадлежность собственных записей; изменённые или чужие файлы сохраняются.

## Запуск

После слияния исправления в main команда установки остаётся прежней:

```sh
curl -fL https://raw.githubusercontent.com/pioner22/MacOS/main/vpn.sh | bash
```

В начале отображается `BigSurVPN 2.1.3`. В меню выбрать `2` для резервного SOCKS5 или `1` для прежних VLESS/Trojan-профилей. Профиль, реквизиты, логика sing-box, DNS и маршрутов этой версией не меняются.

После успешной установки полный путь доступен сразу:

```sh
/Library/BigSurVPN/vpn-bigsur status
```

Для короткого `vpn-bigsur` открыть новую вкладку/окно Терминала с обычной login-shell, чтобы macOS применила новую запись PATH. Уже работающая родительская оболочка не может получить новый PATH от скрипта, запущенного через `curl | bash`. При нестандартной настройке оболочки или конфликтующей чужой команде следует использовать полный путь.

Команды сохранены: `status`, `test`, `report`, `off`, `on`, `--help`, `--version`. Справка и версия не требуют sudo. Ожидаемая версия и загрузчика, и установленного runtime — 2.1.3.

Повторный локальный прогон: **196 тестов, 196 успешных, 0 пропусков**, 7.861 секунды. Linux x86_64, Python 3.13.5, GNU Bash 5.2.37, root с непривилегированными дочерними процессами.

```sh

bash -n vpn.sh
python3 -m py_compile vpn-runtime.py
```

Состав: 52 проверки прав/CLI, 19 проверок доставки загрузчика, 17 жизненного цикла, 65 SOCKS5/меню и 43 новых проверки альтернативного пути команды. Новые проверки используют реальные временные файлы, режимы 0775/0777/0700/0750/0000, пользовательских владельцев, ссылки и чужие файлы. Подтверждены сохранность общего каталога, запуск справки непривилегированным пользователем, недоступность приватного файла, повторная установка, регистрация/очистка PATH и проход через настоящее меню/активацию файлов при 0775. Сеть, ядро и launchd в сценариях установки подменены.

Git blob всех пяти изменённых/добавленных программных файлов и тестов совпал с локальными проверенными байтами. SHA-256 фактического runtime совпал с закреплением загрузчика. По сравнению с исходным runtime изменены только четыре существующие функции: `check_activation_paths`, `activate_install`, `setup`, `main`; добавлены семь функций управления путём команды. Остальные 69 исходных функций/классов не изменены по AST.

Это не полный аудит репозитория, не PASS GitHub Actions и не проверка живого VPN. Настоящие macOS Big Sur, Python 2.7, Bash 3.2, ACL macOS, launchd, TUN, DNS и доступность SOCKS5 с Mac здесь не проверялись. Локальные успехи не объявляются подтверждением подключения устройства пользователя.
